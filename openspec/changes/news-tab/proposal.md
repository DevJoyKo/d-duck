## Why
사용자 요청(2026-11-11, D-204): "Claude는 기능을 매우 빠르게 내놓는다. 새 기능마다 무엇인지, 언제 쓰면 좋은지, 베스트 프랙티스를 설명하는 소식 탭을 만들어 줘. 최신이 위, 예전 것은 아래 보관. Medium처럼 왼쪽 썸네일, 오른쪽 제목과 한 줄 요약(날짜). 매일 새로 고치거나 눌러서 가져오기."

Claude Code는 거의 매일 버전을 낸다(2026-11-10 기준 2.1.322). 변경 기록은 한 줄짜리 목록이라 "이걸 내 작업에 언제 쓰지?"는 사용자가 직접 찾아야 한다. D.Duck은 이미 사용자가 로그인한 `claude` CLI로 확인을 받고 한 번 돌리는 유료 작업(사용 개선 분석, D-078)을 안전하게 하는 길이 있다. 같은 길로 공식 출처만 읽혀 기능 설명을 받아 로컬에 쌓는다.

## What Changes
- **소식 탭**: 사이드바 아래 묶음(사용 통계·설정 위)에 "소식"(en: News). 왼쪽 120px 카테고리 썸네일, 오른쪽 제목·한 줄 요약·`버전 · 날짜`인 Medium형 줄. 최신이 위. 30일보다 오래된 소식은 "이미 나온 기능"(en: Earlier) 묶음으로 아래에. 안 본 소식에는 "새 소식" 점.
- **상세**: 줄을 누르면 오른쪽 시트에 무엇인지 / 언제 쓰면 좋은지 / 베스트 프랙티스 / 원문 열기(브라우저). 열면 본 것으로 표시.
- **가져오기**: 버튼 하나. 셸이 예상 비용과 보내는 것을 네이티브 확인 창으로 보이고, 확인하면 `claude -p` 한 번(웹 읽기만, 허용한 공식 주소만, 예산·시간·횟수 상한, 앱 소유 빈 폴더). 답은 엄격한 JSON. Rust가 스키마·길이·주소를 검사해 잘못된 항목은 버리고, 통과한 것만 id로 합친다. 실패해도 예전 소식은 그대로. 이미 가진 id를 프롬프트에 넣어 새 것만 받는다.
- **매일 가져오기**: 탭의 스위치 하나, 기본 꺼짐. 켤 때 한 번 네이티브 확인(하루 한 번·회당 상한·월 최대). 앱이 켜져 있는 동안 24시간마다 같은 가져오기를 확인 없이 한 번. claude.ai 클라우드 루틴은 만들지 않는다.
- **썸네일**: 카테고리 카드(아이콘 + 오리 팔레트 색). 원격 이미지는 받지 않고 CSP도 그대로.
- **언어**: 앱 언어로 만들고 언어별로 저장한다. 다른 언어로 바꾸면 그 언어의 소식이 보이고, 없으면 그 언어로 가져오라고 안내한다.
- 상태 줄: 마지막으로 가져온 시각, 결과(새 소식 n개 / 실패 이유), 비용.

## Capabilities
### New Capabilities
- `claude-news`: 공식 출처에서 Claude Code 새 기능 설명을 가져와 검사·저장하고 소식 탭에 보이는 일, 매일 가져오기.

### Modified Capabilities
- `nav-ia`: 사이드바 아래 묶음에 "소식" 추가.

## Impact
- core: 새 모듈 `news`(출처 허용 목록, 가드 판정, 프롬프트·인자, 출력 검사, 합치기·목록·본 표시, 상태·매일 설정), DB 마이그레이션 v17(`news_items`), i18n 코드(확인 창·실패 문구).
- shell: `news_cmds.rs`(명령 `news_list`·`news_fetch`·`news_cancel`·`news_mark_seen`·`news_set_daily`·`news_open_source`, 스케줄러 틱), `main.rs` 가드 모드 `--dduck-guard-news`.
- webview: `NewsPage`, nav `news`, i18n `news` 네임스페이스, api, mock(12개, 카테고리 고루), vitest.
- 비용: 수동 1회 약 $0.10–0.30, 최대 $0.40(API 환산). 매일 켜면 30일 최대 $12.
