# Proposal

## Why

사용자(2026-11-11): 일을 맡길 때 Claude가 늘 쓰던 스킬·에이전트만 고르고, 사용자가 일부러 설치한 스킬 묶음(예: 어떤 플러그인)은 거의 후보로 보지 않는다. 사용자는 "먼저 이것들을 검토해 보라"고 한 번 정해 두고 싶어 한다. 앱은 오픈소스이므로 특정 플러그인 이름을 넣지 않고 일반 설정으로 만든다.

## What Changes

- 에이전트 설정 시트의 **팀 규칙** 탭에 "먼저 검토할 스킬·에이전트" 칸을 둔다. 지금 설치되어 보이는 것 중에서만 고른다.
  - 플러그인(그 플러그인의 스킬·에이전트 전부), 스킬·명령 하나, 에이전트(사용자·프로젝트·플러그인)
  - 최대 10개
  - 목록은 확장 탭·에이전트 탭이 쓰는 같은 읽기 함수(`skills_catalog::discover`, `agents_catalog::discover`)로 만든다
- 고른 목록은 팀 설정(`team_config`)에 다른 항목처럼 **기본값과의 차이**로 저장한다. 기본값은 빈 목록이다. 기본값으로 되돌리기·전체 초기화·검증 실패 시 버리기 규칙도 다른 항목과 같다.
- 작업을 시작할 때 팀 규칙 끝(근거 규칙 다음, 푸시 알림 규칙 앞)에 앱이 만든 `[필수]` 한 줄을 시작 언어로 넣는다. 지금 그 작업 폴더에서 보이는 항목만 넣고, 이름과 한 줄 설명을 붙인다.
  - 설명은 정리해서 넣는다: 줄바꿈 없음, 길이 제한, 대괄호를 괄호로 바꿔 표식 흉내를 막음, 전체 길이 제한
  - 설치되지 않은 항목은 시작할 때 빼고, 설정 화면에서는 "설치되지 않음"으로 보인다
- 같은 줄을 팀 규칙이 붙는 다른 경로에도 넣는다: 로컬 루틴 실행, 한도 리셋 뒤 이어서 하기(재개). 재작업은 새 작업 시작(`start_task`)을 거치므로 따로 할 일이 없다. 스킬 만들기 작업(authoring)은 팀 규칙 대신 고정 안내를 쓰므로 넣지 않는다.
- 문구는 정직하게: 화면과 README 두 곳 모두 "프롬프트 수준의 안내이며 deny 규칙·훅 같은 강제 가드레일이 아니다"를 적는다.

## Capabilities

### New Capabilities
- `preferred-skills`: 먼저 검토할 스킬·에이전트를 고르고, 작업 시작 시 설치된 것만 한 줄 안내로 넣는다

### Modified Capabilities
- 없음 (team-presets-editable의 팀 설정 저장 규칙을 그대로 따른다)

## Impact

- core: 새 모듈 `preferred.rs`(항목·검증·목록 만들기·줄 만들기), `team_config.rs`(`Stored`·`Merged`·`TeamInput`·`reset_item`·정책 줄 끼우기), `loadout::Env`에 시작 폴더의 목록, `claude_cli::prepare_with`, `routines`(실행 직전 줄 넣기)
- 셸: `preferred_options` 명령, `loadout_env`가 목록을 채움(고른 항목이 있을 때만 읽음), 루틴 시작 전 줄 넣기
- UI: `PreferredSection`(팀 규칙 탭), `lib/team.ts` 타입·저장, mock, i18n ko·en
- README.md·README.ko.md 가드레일 절
- 범위 밖: 플러그인 켜짐/꺼짐(`enabledPlugins`) 판단. 캐시에 있는 플러그인은 꺼져 있어도 "보이는 것"으로 친다(design 결정 3).
