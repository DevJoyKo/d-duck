# Proposal

## Why

소식 탭 썸네일은 카테고리 색과 아이콘뿐이라 무엇을 써 보면 되는지 알려 주지 않는다(사용자: "썸네일이 영양가 없는데?"). 소식을 읽은 뒤 내 프로젝트에 적용하려면 내용을 다시 정리해 작업을 직접 써야 해서, 읽기와 적용 사이가 끊겨 있다(사용자: "기존 프로젝트에 후딱 적용할 수 있게 '적용 제안', 브릿지 되게").

## What Changes

- 썸네일을 "핵심 카드"로 바꾼다(사용자 선택 B). 가장 중요한 사실 하나(`/diff`, "effort 상한", "1M 컨텍스트")를 크게 보이고, 아래에 적용 방법 태그(바로 됨 / 설정 필요 / 골라 쓰기)를 단다. 핵심이 없거나 예전 소식이면 지금의 카테고리 카드를 그대로 쓴다.
- 상세 시트에 "적용 제안"을 더한다. 프로젝트에 넣는 1–3단계와 "됐는지 확인하는 법" 한 줄.
- 시트에서 대상 프로젝트(기본: 최근 프로젝트)를 고르고 "내 프로젝트에 적용"을 누르면 작업 작성 창을 채운 초안으로 연다(브릿지). 대상이 비면 작성 창에서 고른다. 계획 모드로 고정하고 "질문 받기로 다듬기"를 권한다. 스스로 시작하지 않는다.
- 가져오기 프롬프트와 검증에 선택 필드 `key_fact`·`adopt`·`apply_steps`·`verify`를 더하고, DB v18에 열을 더한다.

## Capabilities

### New Capabilities
- `news-apply`: 소식의 핵심 카드와 적용 제안, 소식에서 작업 초안으로 넘어가는 브릿지.

### Modified Capabilities
- 없음. `claude-news`(news-tab, 아직 아카이브 전)의 카테고리 썸네일은 핵심이 없는 소식의 대체로 남는다. news-tab 아카이브 뒤 이 change를 아카이브할 때 `claude-news` 목록 요구사항의 썸네일 문장을 맞춘다.

## Impact

- `app/crates/dduck-core/src/news.rs`(프롬프트·파싱·저장·마이그레이션 v18), `claude_cli.rs`(작업 출처 `news`), `task_meta`·db 출처 저장.
- `app/src/components/NewsPage.tsx`(썸네일·시트), `lib/brief.ts`·`lib/refine.ts`(초안), `Composer.tsx`(출처 배지·계획 고정), `App.tsx`(openDraft 연결), i18n ko/en, mock 소식 데이터.
- 한 번 가져오기의 출력이 늘어 비용이 조금 오를 수 있다(상한 $0.40은 그대로).
