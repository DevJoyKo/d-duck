## ADDED Requirements

### Requirement: 재작업 요청 진입점
보고서가 준비된 끝난 작업에는 두 곳에 "재작업 요청" 버튼이 있어야 한다(SHALL): 리뷰 카드의 "리뷰했어요" 왼쪽, 보고서 화면 아래 줄(리뷰 탭·작업 탭·작업 보드 리뷰 대기 카드에서 연 보고서 공통). 이 버튼은 노랑 강조를 쓰지 않아야 한다(MUST NOT). 실행 중이거나 답을 기다리는 작업, 보고서가 없는 작업에는 버튼이 없어야 한다(SHALL NOT 표시). 보고서 형식이 맞지 않으면 기준 목록 없이 "새 작업으로"만 고를 수 있어야 한다(SHALL).

#### Scenario: 리뷰 카드에서
- **WHEN** 리뷰 전 카드가 끝난 개발 작업이고 보고서가 준비되어 있다
- **THEN** 카드 오른쪽에 "재작업 요청"(일반 버튼)과 "리뷰했어요"가 나란히 보인다

#### Scenario: 실행 중
- **WHEN** 작업이 아직 일하는 중이다
- **THEN** 카드와 보고서 화면 어디에도 "재작업 요청"이 없다

### Requirement: 고르기 위주의 재작업 시트
"재작업 요청"을 누르면 시트가 열려야 하고(SHALL), 시트는 위에서부터 한 줄씩 다음을 보여야 한다(SHALL): ① "어떤 기준을 다시 볼까요?" 완료 기준 체크 목록 ② "무엇이 아쉬웠나요?" 이유 칩 5개(근거 부족·기준 미충족·범위 밖 수정·합의와 다름·기타) ③ "한 줄 덧붙이기(선택)" 입력 하나(120자까지, 한 줄) ④ "어떻게 다시 할까요?" 선택 두 개(같은 세션에서 이어서 / 새 작업으로) ⑤ 접힌 "이렇게 전해요" 미리보기 ⑥ 주 버튼과 "취소". 기준 목록에는 못 했어요·일부 충족·근거 없음·대조 안 함인 기준이 미리 체크되어 있어야 한다(SHALL). 이유는 근거 없음이 있으면 "근거 부족", 못 했어요가 있으면 "기준 미충족", 합의와 다름 결정이 있으면 "합의와 다름"이 미리 골라져 있어야 한다(SHALL). 이유가 하나도 없거나 "기타"만 골랐는데 한 줄이 비어 있으면 주 버튼이 비활성이어야 한다(SHALL). 노랑은 주 버튼 하나에만 쓰고(SHALL), 문구는 해요체이며 "리뷰"를 써야 한다(SHALL).

#### Scenario: 미리 채워진 시트
- **WHEN** 기준 3개 중 충족 1(근거 있음), 충족 1(근거 없음), 못 했어요 1인 보고서에서 "재작업 요청"을 누른다
- **THEN** 근거 없는 충족 기준과 못 했어요 기준이 체크되어 있고, 이유 칩 "근거 부족"·"기준 미충족"이 골라져 있으며, 아무것도 입력하지 않고 주 버튼을 누를 수 있다

#### Scenario: 기타만 고름
- **WHEN** 사용자가 다른 이유를 모두 끄고 "기타"만 고르고 한 줄을 비워 둔다
- **THEN** 주 버튼이 비활성이고 "기타를 고르면 한 줄을 적어 주세요"가 보인다

### Requirement: 다시 하는 방법
"새 작업으로"는 늘 고를 수 있어야 한다(SHALL). 누르면 Composer가 원래 브리프·유형·권한 모드로 열리고, 브리프 위에 읽기 전용 "재작업 요청" 블록(이유·기준·한 줄)과 "'이름'의 재작업" 배지가 있어야 한다(SHALL). 원래 작업이 worktree에서 돌았고 그 worktree가 남아 있으면 그 폴더에서 worktree 없이 시작하도록 채워져야 하며(SHALL), 없어졌으면 프로젝트 폴더로 채우고 "원래 worktree가 없어 프로젝트 폴더에서 시작해요"를 보여야 한다(SHALL). "같은 세션에서 이어서"는 이전 대화를 이을 수 있을 때(세션을 알고, 원격 조작·루틴이 아니고, 세션 폴더가 안전 검사를 통과할 때)만 고를 수 있어야 하고(SHALL), 아니면 비활성과 이유 한 줄을 보여야 한다(SHALL). 이어서 하기는 시작 때와 같은 팀 규칙·보고서 지시·허용 도구·역할·전달 범위 규칙을 다시 붙여야 하며(SHALL), 위험 권한 모드면 기존 네이티브 확인을 거쳐야 한다(SHALL). 기본 선택은 이어서 하기가 가능하고 이유가 "근거 부족" 하나뿐일 때 "같은 세션에서 이어서", 그 밖에는 "새 작업으로"여야 한다(SHALL).

#### Scenario: 새 작업으로
- **WHEN** 사용자가 "새 작업으로"를 고르고 "새 작업으로 열기"를 누른다
- **THEN** Composer가 원래 브리프로 열리고 재작업 요청 블록이 보이며, 사용자가 "시작"을 누르기 전에는 아무 작업도 시작되지 않는다

#### Scenario: 이어서 할 수 없음
- **WHEN** 원래 작업의 세션을 알 수 없다
- **THEN** "같은 세션에서 이어서"는 비활성이고 "이전 대화를 찾을 수 없어요"가 보이며 "새 작업으로"가 골라져 있다

#### Scenario: 근거만 부족
- **WHEN** 이어서 하기가 가능하고 이유가 "근거 부족"뿐이다
- **THEN** "같은 세션에서 이어서"가 추천 배지와 함께 골라져 있고, 주 버튼은 "이어서 시작"이다

### Requirement: 같은 실행 조건
재작업은 두 방법 모두 원래 작업의 유형·권한 모드·에이전트·노력 수준·모델을 그대로 써야 한다(SHALL). 새 작업으로 연 Composer에서 사용자가 모델을 바꾸면 재작업 블록에 "모델을 바꿨어요"가 남아야 한다(SHALL). 원래 작업의 모델 기록이 없으면 모델을 지정하지 않아야 한다(SHALL).

#### Scenario: 모델 유지
- **WHEN** 원래 작업이 특정 모델로 돌았고 사용자가 "같은 세션에서 이어서"로 재작업을 시작한다
- **THEN** 재작업은 같은 모델·유형·권한 모드로 시작된다

### Requirement: 앱이 만드는 피드백
재작업으로 Claude에 보내는 피드백 글은 앱이 고른 값으로만 만들어야 한다(SHALL): 고정 이유 문구, 원래 브리프의 완료 기준이나 원래 보고서에 있던 기준 문구, 사용자의 한 줄. 앱은 원래 보고서·브리프에 없는 기준 문구, 열거 밖 이유, 120자를 넘거나 여러 줄인 한 줄을 거부해야 한다(SHALL). 에이전트가 쓴 근거 글·이유 글은 피드백에 넣지 않아야 한다(MUST NOT). 시트의 "이렇게 전해요"는 실제로 보낼 글과 같아야 한다(SHALL).

#### Scenario: 조작된 기준
- **WHEN** 웹뷰가 원래 보고서·브리프에 없는 기준 문구를 담아 재작업을 시작하려 한다
- **THEN** 앱은 시작을 거부하고 아무 작업도 시작되지 않는다

### Requirement: 원래 작업과 이어진 새 작업
재작업으로 시작한 작업은 이어서 하기든 새 작업이든 새 작업 기록이어야 하고(SHALL), 원래 작업을 가리키는 연결과 재작업 요청(이유·기준·한 줄·방법)을 함께 남겨야 한다(SHALL). 새 보고서 폴더를 받아야 하며 원래 보고서는 그대로 남아야 한다(SHALL). "작업 지시 저장"이 꺼져 있으면 이유와 방법만 남기고 기준·한 줄은 남기지 않아야 한다(SHALL). 재작업이 시작되면 원래 작업은 리뷰 전·배지·작업 보드 리뷰 대기에서 빠지고 정리 칸으로 가야 하며(SHALL, 리뷰했어요 표시는 바꾸지 않음), 원래 카드는 "재작업 → 새 작업"을 보여야 하고 누르면 새 작업 카드로 가야 한다(SHALL). 새 작업 카드는 "재작업" 칩과 "← 원래 작업"을 보여야 한다(SHALL). 원래 작업 기록이 지워졌으면 "원래 작업 기록이 지워졌어요"를 보여야 한다(SHALL). 재작업을 취소하거나 Composer를 닫으면 아무것도 바뀌지 않아야 한다(SHALL).

#### Scenario: 원래 카드
- **WHEN** 리뷰 전이던 작업 A에서 재작업을 새 작업 B로 시작한다
- **THEN** A는 리뷰 전 필터·배지·리뷰 대기 칸에서 빠지고, 작업 보드 정리 칸과 리뷰 탭 전체 필터에서 "재작업 → 새 작업"과 함께 보이며, B는 같은 역할 묶음에 "재작업" 칩과 함께 일하는 중으로 보인다

#### Scenario: 취소
- **WHEN** 사용자가 재작업 시트에서 "새 작업으로 열기"를 누른 뒤 Composer를 닫는다
- **THEN** A는 여전히 리뷰 전이고 연결이 기록되지 않는다

### Requirement: 새 보고서의 재작업 블록
재작업 작업의 보고서 "맡긴 내용" 아래에는 앱이 기록한 "재작업 요청" 블록(이유 칩, 다시 볼 기준, 한 줄, 다시 한 방법, "원래 작업 보고서 보기")이 있어야 한다(SHALL). 이 블록은 에이전트가 바꿀 수 없어야 한다(SHALL, 보고서 파일이 아니라 앱 기록에서 읽음).

#### Scenario: 재작업 보고서
- **WHEN** 사용자가 재작업 B의 보고서를 연다
- **THEN** 맡긴 내용 아래에 "재작업 요청 · 근거 부족 · 기준 미충족"과 다시 볼 기준 2줄, 한 줄, "새 작업으로"가 보이고, "원래 작업 보고서 보기"를 누르면 A의 보고서가 열린다
