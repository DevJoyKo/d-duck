# Spec Delta

## Purpose
D.Duck의 색 체계를 정한다. 사이드바와 화면 바탕은 중성색으로 조용하게 두고, 남색은 글자와 주 버튼에, 오리 노랑은 화면당 한 곳의 강조에만 쓴다.

## ADDED Requirements

### Requirement: 중성색 사이드바
사이드바는 꽉 채운 남색이 아니라 화면 바탕과 같은 계열의 중성색이어야 한다(SHALL). 라이트에서는 밝은 반투명, 다크에서는 흑연색 반투명이다. 선택된 항목은 옅은 바탕과 진한 글자, 얇은 중성색 막대로 표시해야 하고(SHALL), 배지는 지금 규칙을 따른다(답 기다림만 노랑).

#### Scenario: 라이트 사이드바
- **WHEN** 라이트 테마에서 작업 탭을 연다
- **THEN** 사이드바 바탕은 밝은 중성색이고, 남색 면은 화면에서 주 버튼 말고는 보이지 않는다

#### Scenario: 다크 사이드바
- **WHEN** 다크 테마로 바꾼다
- **THEN** 사이드바와 바탕은 흑연색 계열이고 남색 계열 바탕이 남아 있지 않다

### Requirement: 색 토큰과 대비
라이트와 다크는 각자 정해진 토큰(잉크·보조·메타 글자, 바탕, 카드, 선, 상태색)을 써야 하며(SHALL), 컴포넌트에 남색 값(#222854 등)을 직접 쓰지 않아야 한다(MUST NOT, 오리 그림 제외). 본문과 보조 글자는 바탕 대비 4.5:1 이상이어야 한다(SHALL).

#### Scenario: 하드코딩 없음
- **WHEN** 화면 소스에서 옛 남색 값을 검색한다
- **THEN** 오리 그림 파일 말고는 나오지 않는다

#### Scenario: 대비
- **WHEN** 라이트·다크의 메타 글자와 카드 바탕 대비를 잰다
- **THEN** 둘 다 4.5:1 이상이다

### Requirement: 카드 위계와 노랑 한 곳
카드는 굵은 테두리 대신 옅은 선과 그림자로 구분해야 한다(SHALL). 사용자를 기다리는 항목(답 기다림 카드, 막힌 작업 안내)은 한 단계 높은 그림자와 노랑 강조를 받아야 한다(SHALL). 노랑 면·링 강조는 화면당 한 종류여야 하며(SHALL), 허용 목록은 다음과 같다.
- 답 기다림 카드: 여러 개면 모두 같은 링을 받는다.
- 막힌 작업 안내
- 사이드바의 답 기다림 배지
- 오리 그림 안의 노랑(부리·발)

이 밖의 칸 머리, 상태 점, 상세 안내 줄은 노랑 대신 한도색(amber)이나 잉크를 써야 한다(SHALL). 대기 카드의 노랑 링과 선택 링·키보드 포커스 링은 서로 다른 모양이어야 한다(SHALL, 예: 선택은 안쪽 잉크 2px, 포커스는 바깥 outline). 작업 보드의 칸은 테두리 없는 옅은 바탕 위에 카드가 놓여야 한다(SHALL).

#### Scenario: 답 기다림 카드
- **WHEN** 작업 보드에 답을 기다리는 작업이 하나 있다
- **THEN** 그 카드만 노랑 링과 높은 그림자를 갖고, 다른 카드에는 노랑이 없다

### Requirement: 역할 오리 그림
역할 오리는 다듬은 조약돌 그림체(D-177)로 그려야 한다(SHALL). 외곽선 없이 몸통 색보다 어두운 같은 계열의 평면 면으로 음영을 넣고, 부리·발은 2톤, 볼 터치를 넣으며, 소품(허리띠·비니·나비넥타이)의 뜻과 역할 색은 유지한다(SHALL). 상태(일하는 중·답 기다림·실패·쉬는 중)는 표정·자세·기호로 구분되어 색 없이도 알아볼 수 있어야 한다(SHALL). 32px·20px에서는 단순화판을 쓰고, 다크 바탕에서도 오리가 바탕과 구분되어야 한다(SHALL).
#### Scenario: 다크에서 오리
- **WHEN** 다크 테마에서 에이전트 화면을 본다
- **THEN** 오리 그림은 라이트와 같은 다듬은 조약돌 그림체이고, 오리 무대가 바탕과 구분된다

### Requirement: 화면 위계 다듬기
페이지 제목·카드 제목·본문·메타는 정해진 크기 단계(20·14·13·12)를 따라야 한다(SHALL). 작업 화면 머리에는 지금 할 일을 세는 한 줄 요약이 있어야 하며(SHALL), 이 요약에는 개수만 들어가고 작업 이름·경로는 넣지 않는다(MUST NOT). 작업 카드의 동작 버튼은 카드 안 아래쪽에 모여야 하며 카드 밖에 떠 있지 않아야 한다(SHALL). 버튼 안에 버튼이 들어가지 않아야 하고(MUST NOT), 동작 버튼을 눌러도 카드 선택이 함께 일어나지 않아야 한다(SHALL). 강제 종료·기록 지우기처럼 되돌릴 수 없는 동작은 카드로 옮기지 않는다(MUST NOT). 역할 표시는 작은 오리 칩과 글자 메타로 하고, 카드마다 알약 배지를 여러 개 붙이지 않아야 한다(SHALL, 상태 경고 배지는 예외).

#### Scenario: 보드 카드 동작
- **WHEN** 리뷰 대기 칸에 한도로 멈춘 작업 카드가 있다
- **THEN** "지금 이어서"·"이번엔 안 이어요" 버튼이 그 카드 안 아래쪽 구분선 밑에 있다

#### Scenario: 머리 요약
- **WHEN** 답을 기다리는 작업 1개와 리뷰 대기 작업 5개가 있다
- **THEN** 작업 화면 제목 옆에 "답을 기다리는 작업 1개, 리뷰할 작업 5개"가 보인다

#### Scenario: 좁은 창에서 상세 서랍
- **WHEN** 900px 창에서 작업 카드를 눌러 상세 서랍을 연다
- **THEN** 보드는 서랍 폭만큼만 줄고 카드 제목이 읽힐 만큼(카드 폭 200px 이상 또는 가로 스크롤) 남는다
