# Proposal

## Why

D.Duck은 모든 화면 문구, 트레이 메뉴, OS 알림, 확인 창, 백엔드 오류를 한국어로 고정해 두었다. UI 문자열 약 2,100줄과 Rust 문자열 약 1,600줄이 코드 곳곳에 흩어져 있다. 그래서 영어를 쓰는 사용자에게 줄 수 없고, 문구를 바꾸려면 컴포넌트를 하나씩 찾아 고쳐야 한다. 사용자가 언어 설정을 요청했다("언어 설정 해줘, i18n").

## What Changes

- 설정에 **언어** 항목을 추가한다. 선택지는 시스템 언어 따름(기본) · 한국어 · English 세 가지다.
  - "시스템 언어 따름"이면 OS 언어가 한국어일 때 한국어, 그 밖에는 영어를 쓴다.
  - 바꾸면 재시작 없이 바로 적용한다.
- 화면 문구 전체를 언어별 **메시지 카탈로그**로 옮긴다.
  - 한국어와 영어는 같은 키 집합을 가져야 하고, 빠진 키는 테스트에서 실패한다.
  - 컴포넌트에 남은 하드코딩 한글은 검사로 막는다.
- **백엔드 문구**를 정리한다.
  - IPC로 UI에 가는 사용자용 오류·거절 이유는 `코드 + 파라미터`로 바꾸고, UI가 번역한다.
  - 트레이 메뉴, OS 알림, 네이티브 확인 창은 UI를 거치지 않으므로 Rust가 저장된 언어로 직접 만든다.
- 날짜·시간·숫자·상대 시간 형식을 언어에 맞춘다. 지금은 `ko-KR`로 고정되어 있다.
- 리포트, 그릴링 질문, 요구사항 다듬기처럼 **Claude에게 보내는 프롬프트**는 답을 앱 언어로 달라고 요청한다.
  - 사용자가 쓴 목표·브리프·작업 이름 같은 내용은 번역하지 않는다.
- 문구 규칙을 언어별로 나눈다.
  - 한국어: 해요체, 항목당 한 줄, "리뷰"(D-109·copy-sweep)
  - 영어: 평이한 문장, sentence case, 항목당 한 줄
- 바뀌지 않는 것: 저장 데이터 형식, 프롬프트 원문 비저장, 자격증명 비접근.

## Capabilities

### New Capabilities
- `app-language`: 언어 선택과 적용 범위(화면·백엔드 문구·OS 표면·형식·Claude 응답 언어), 카탈로그 완전성, 하드코딩 금지.

### Modified Capabilities
- 없음. copy-tone(문구 통일)은 한국어 카탈로그에 그대로 적용된다. 영어 규칙은 app-language에 둔다.

## Impact

- **UI**
  - `app/src/**` 거의 모든 컴포넌트의 문구를 카탈로그 키로 바꾼다.
  - `src/lib/format.ts`의 locale을 언어에 맞춘다.
  - `SettingsPage`에 언어 항목을 추가한다.
  - mock 서버에서 `?lang=en`을 지원한다.
- **Rust**
  - dduck-core에 언어 설정 값(`ui.language`)과 작은 메시지 테이블을 추가한다.
  - 사용자용 오류를 코드화하고, 트레이·알림·확인 창 문구를 언어에 맞춘다.
  - brief_refine·grilling·report 프롬프트에 응답 언어 지시를 넣는다.
- **테스트**
  - 카탈로그 완전성과 파라미터 일치 검사
  - 하드코딩 한글 검사(허용 목록 포함)
  - copyRules를 언어별로 분리
  - 영어로 900px 화면에서 잘림이 없는지 스크린샷으로 확인
- **의존성**: 새 라이브러리는 넣지 않는다. 자체 경량 `t()`와 `Intl`을 쓴다.
