# Spec Delta

## ADDED Requirements

### Requirement: 카드 삭제
리뷰 탭의 끝난 카드(보고서 있는 작업, 보고서 없는 작업, 루틴 실행)마다 "삭제"가 있어야 한다(SHALL). 실행 중·답을 기다리는 카드와 실행 여부를 아직 모르는 카드, 시작 중인 루틴 실행에는 없어야 한다(MUST NOT). 삭제는 앱의 네이티브 확인 창을 거쳐야 하며(SHALL), 창은 지워지는 것(작업 기록과 보고서의 근거·첨부, 되돌릴 수 없음)과 남는 것(Claude 세션 기록, git worktree·브랜치)을 말해야 한다(SHALL). worktree로 시작한 작업이면 먼저 정리하라는 줄을 더해야 한다(SHALL). CLI 목록에 아직 있는 세션은 지운 뒤 보드에 다시 나오지 않아야 한다(MUST NOT). 작업 기록은 지난 작업 삭제와 같이 기록·지시·보고서 폴더를 지운다(SHALL). 루틴 실행은 보고서 폴더와 보고서 연결·리뷰 상태만 지우고 실행 기록은 남긴다(SHALL). 앱은 실행 중인 작업, 이어서 하기가 예약된 작업, 확인 창이 열린 동안 다시 시작된 작업의 삭제를 거절해야 한다(SHALL). 지운 뒤 배지·보드 리뷰 대기와 정리 칸·리뷰 탭 수가 바로 바뀌고 포커스는 다음 카드로 가야 한다(SHALL). 보고서 폴더는 보고서 루트 안의 올바른 id 폴더만 지워야 한다(SHALL).

#### Scenario: 보고서 있는 작업 삭제
- **WHEN** 리뷰 전 카드의 "삭제"를 누르고 확인 창에서 "삭제"를 고른다
- **THEN** 카드가 사라지고 배지와 리뷰 대기 칸이 1 줄며, 지난 작업에서도 사라지고 보고서 폴더가 없어진다

#### Scenario: 취소
- **WHEN** 확인 창에서 "취소"를 고른다
- **THEN** 아무것도 바뀌지 않는다

#### Scenario: 루틴 실행 삭제
- **WHEN** 루틴 실행 카드를 지운다
- **THEN** 리뷰 탭과 배지에서 빠지고 보고서 폴더가 없어지며, 루틴 탭 실행 기록에는 그 실행이 남는다

#### Scenario: 실행 중
- **WHEN** 작업이 아직 일하는 중이다
- **THEN** 카드에 "삭제"가 없고, 명령을 직접 보내도 거절된다

#### Scenario: worktree가 남은 작업
- **WHEN** worktree로 시작해 정리 끝을 누르지 않은 작업을 지우려 한다
- **THEN** 확인 창에 "먼저 작업 탭 정리에서 worktree를 지우세요" 줄이 있다

#### Scenario: 보고서 없는 작업 삭제
- **WHEN** 전체 필터의 "보고서 없음" 카드를 지운다
- **THEN** 카드가 사라지고 지난 작업에서도 사라지며 배지는 그대로다

#### Scenario: 이어서 하기가 예약된 작업
- **WHEN** 사용 한도 뒤 이어서 하기가 예약된 작업을 지우려 한다
- **THEN** 앱이 거절하고 오류 줄에 이유가 보인다

#### Scenario: 확인 창이 열린 동안 다시 시작
- **WHEN** 확인 창이 열린 동안 그 작업이 다시 일하기 시작하고 사용자가 "삭제"를 고른다
- **THEN** 앱이 거절하고 아무것도 지우지 않는다

#### Scenario: 목록에 남은 세션
- **WHEN** CLI 목록에 아직 있는 끝난 작업을 지운다
- **THEN** 작업 보드 어느 칸에도 다시 나오지 않는다

#### Scenario: 포커스
- **WHEN** 카드를 지운다
- **THEN** 포커스가 다음 카드의 열기 버튼으로 간다(없으면 앞 카드)

#### Scenario: 보고서 폴더 경로
- **WHEN** 보고서 루트가 링크이거나 기록의 보고서 id가 올바르지 않다
- **THEN** 루트 밖이나 다른 폴더는 지우지 않는다
