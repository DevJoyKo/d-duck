## ADDED Requirements

### Requirement: 리뷰를 해야 끝나는 작업
에이전트가 일을 끝냈지만 리뷰하지 않은 작업은 앱 어디에서도(작업 보드 칸, 상태 칩, 알림, 트레이 툴팁, 리뷰 탭, 보고서 머리) "완료"라고 부르지 않아야 한다(MUST NOT). 그런 작업은 "오리가 끝냈어요 · 리뷰 대기"로 보여야 한다(SHALL). "완료"는 리뷰하고 "정리 끝"을 누른 작업에만 써야 한다(SHALL). 루틴 실행 상태는 "끝났어요"로 보여야 한다(SHALL).

#### Scenario: 끝남 알림
- **WHEN** 보고서가 붙은 작업을 에이전트가 끝내고 끝남·실패 알림이 켜져 있다
- **THEN** macOS 알림은 "오리가 끝냈어요 · 리뷰 대기: <작업 이름>"이고 "완료"가 없다

#### Scenario: 상태 칩
- **WHEN** 사용자가 작업 탭에서 끝났지만 리뷰하지 않은 작업 카드를 본다
- **THEN** 상태 칸은 "오리가 끝냈어요 · 리뷰 대기"이다

### Requirement: 바꾸지 않는 "완료"·"끝" 문구
다음 넷은 작업 상태가 아니므로 그대로 두어야 한다(SHALL): 브리프 항목 "완료 기준", 온보딩 체크 항목의 "(완료)", 오리 포즈 문구 "방금 끝냈어요", 튜토리얼 문구. 이 넷과 정리 끝 상태 말고는 작업 상태로 "완료"를 쓰지 않아야 한다(MUST NOT).

#### Scenario: 문구 점검
- **WHEN** 앱 소스에서 작업 상태 "완료" 문자열을 찾는다
- **THEN** 정리 끝 상태와 바꾸지 않는 넷 말고는 남아 있지 않다

### Requirement: 작업 보드 칸
작업 보드 칸은 대기 중 → 진행 중 → 확인 필요 → 리뷰 대기 → 정리 순서여야 하고(SHALL), "완료" 칸은 없어야 한다(MUST NOT). 칸 설명은 리뷰 대기 "오리가 끝냈고 리뷰를 기다려요", 정리 "리뷰한 작업의 마무리를 확인해요"여야 한다(SHALL). 같은 작업이 두 칸에 나오지 않아야 한다(MUST NOT). 실행 중인 세션이 하나도 없어도 리뷰 대기·정리 작업이 있으면 보드를 그려야 한다(SHALL).

#### Scenario: 실행 중인 세션 없음
- **WHEN** 살아 있는 세션은 없고 리뷰 대기 작업이 2개 있다
- **THEN** 빈 화면 대신 보드가 보이고 리뷰 대기 칸에 카드 2개가 있다

### Requirement: 리뷰 대기 칸
리뷰 대기 칸은 리뷰 탭의 리뷰 전 작업과 같은 작업이어야 한다(SHALL): 보고서 붙음, 끝남(완료·실패·중지·알 수 없음 또는 목록에 없음), 리뷰 안 함, 리뷰 기준 시각 이후. 칸 머리 수는 사이드바 리뷰 배지와 같아야 하고(SHALL), 작업 목록에서 이미 사라진 작업도 보여야 한다(SHALL). 실패로 끝난 작업은 "실패했어요 · 리뷰 대기", 중지된 작업은 "멈췄어요 · 리뷰 대기"여야 한다(SHALL). 카드는 40개까지 보이고 나머지는 "리뷰 탭에서 모두 보기"여야 한다(SHALL). 카드를 누르면 보고서가 열리고 아래에 "리뷰했어요"가 있어야 한다(SHALL).

#### Scenario: 배지와 같은 수
- **WHEN** 리뷰 탭 배지가 3이고 그중 하나는 실패로 끝난 보고서 작업이다
- **THEN** 리뷰 대기 칸 수가 3이고, 실패 작업은 "실패했어요 · 리뷰 대기"로 리뷰 대기 칸에 있으며 확인 필요 칸에는 없다

#### Scenario: 리뷰했어요
- **WHEN** 사용자가 리뷰 대기 카드의 보고서에서 "리뷰했어요"를 누른다
- **THEN** 카드가 정리 칸으로 옮겨 가고 리뷰 배지와 리뷰 대기 칸 수가 함께 1 준다

### Requirement: 정리 칸에 들어가는 작업
정리 칸에는 리뷰했고 정리 끝을 누르지 않은 D.Duck 작업이 "리뷰했어요 · 정리 남음"으로 보여야 한다(SHALL). 리뷰 대상이 아닌 끝난 세션(리뷰 기준 시각 전, 보고서 없이 끝남, D.Duck 밖에서 시작)은 정리 칸에 24시간만 "리뷰 없이 끝났어요"로 보여야 하고(SHALL), 실패로 끝났으면 지금처럼 확인 필요 칸에 있어야 한다(SHALL). 업데이트 뒤 첫 실행에서 기준 시각 전 작업이 리뷰 대기 칸에 들어가지 않아야 한다(MUST NOT).

#### Scenario: 이전 작업
- **WHEN** 업데이트 전에 끝난 보고서 작업 30개가 있고 앱을 처음 연다
- **THEN** 리뷰 대기 칸은 비어 있고, 그중 24시간 안에 끝난 작업만 정리 칸에 "리뷰 없이 끝났어요"로 보인다

### Requirement: 정리 점검표
정리 카드를 펼치면 로컬에서만 알아낸 사실을 한 줄씩 보여야 하며(SHALL), 네트워크를 쓰지 않아야 한다(MUST NOT): ① worktree 작업이면 "worktree가 남아 있어요 · <폴더 이름> · <브랜치>" 또는 "worktree는 정리됐어요" ② "커밋 안 된 변경 없어요" 또는 "커밋 안 된 변경 N개"(파일 이름 없음) ③ 보고서 레퍼런스에 GitHub PR 주소가 있으면 "보고서에 적힌 PR · #N" ④ 전달 범위가 기록되어 있으면 "로컬만" 또는 "PR 초안까지". 점검은 펼칠 때만 해야 한다(SHALL). 앱이 점검으로 실행하는 git은 저장소 설정의 감시 도구·훅·시스템 설정을 실행하지 않아야 한다(MUST NOT). 점검표는 정리 끝을 막지 않아야 한다(MUST NOT).

#### Scenario: worktree가 남은 작업
- **WHEN** worktree에서 돈 작업을 리뷰했고, 커밋 안 된 변경이 없으며, 보고서에 PR 주소가 있다
- **THEN** 정리 카드에 "worktree가 남아 있어요 · fix-auth · dduck/fix-auth", "커밋 안 된 변경 없어요", "보고서에 적힌 PR · #42"가 한 줄씩 보인다

#### Scenario: fsmonitor가 설정된 저장소
- **WHEN** 저장소 설정의 `core.fsmonitor`가 임의 명령을 가리킨다
- **THEN** 점검표를 펼쳐도 그 명령은 실행되지 않는다

### Requirement: worktree 정리
정리 카드의 "worktree 정리"는 작업이 실행 중이 아니고, worktree가 저장소의 `.claude/worktrees/` 아래 실제 폴더(링크 아님)이고, 커밋 안 된 변경·추적 안 된 파일이 없을 때만 할 수 있어야 하며(SHALL, 아니면 비활성과 이유 한 줄), 네이티브 확인 창(폴더·브랜치, 함께 지워질 무시된 파일 수, "브랜치와 커밋은 남겨요")을 거쳐야 한다(SHALL). 앱은 강제 옵션 없이 worktree만 지우고 브랜치는 지우지 않아야 한다(MUST NOT 지움).

#### Scenario: 변경이 남은 worktree
- **WHEN** 정리 카드의 worktree에 커밋 안 된 변경이 2개 있다
- **THEN** "worktree 정리"는 비활성이고 "커밋 안 된 변경이 있어 정리할 수 없어요"가 보인다

#### Scenario: 무시된 파일
- **WHEN** 변경은 없고 무시된 빌드 파일이 120개 있는 worktree를 정리한다
- **THEN** 확인 창에 "무시된 파일 120개(빌드 결과 등)도 함께 지워져요"가 보이고, 확인하면 worktree만 지워지고 브랜치는 남는다

### Requirement: 정리 끝
"정리 끝"을 누르면 카드가 보드에서 빠지고 5초 동안 "정리 끝 · 되돌리기"가 보여야 하며(SHALL), 그 작업은 리뷰 탭 전체·지난 작업에서 "완료"로 보여야 한다(SHALL). 실행 중이거나 리뷰 대기인 작업은 정리 끝을 할 수 없어야 한다(SHALL). 리뷰했어요를 되돌리면 정리 끝도 함께 풀려 리뷰 대기로 돌아가야 한다(SHALL).

#### Scenario: 정리 끝
- **WHEN** 사용자가 정리 카드의 "정리 끝"을 누른다
- **THEN** 카드가 보드에서 빠지고 "정리 끝 · 되돌리기"가 5초 보이며, 리뷰 탭 전체에서 그 작업 카드에 "완료" 칩이 있다

#### Scenario: 리뷰 되돌리기
- **WHEN** 정리 끝인 작업의 리뷰했어요를 리뷰 탭에서 되돌린다
- **THEN** 그 작업은 "완료"가 아니고 리뷰 대기 칸에 다시 나온다

### Requirement: 트레이와 설정 문구
트레이 툴팁은 확인 필요 수 뒤에 리뷰 대기 수(리뷰 배지와 같은 값)를 보여야 하고(SHALL), 리뷰 대기 수만 바뀌어도 갱신되어야 하며(SHALL), 0인 쪽은 생략해야 한다(SHALL). 설정의 알림 항목 이름은 "끝남·실패 알림", 설명은 "오리가 작업을 끝내거나 실패하면 macOS 알림으로 알려 줘요"여야 한다(SHALL).

#### Scenario: 툴팁
- **WHEN** 확인 필요 1개와 리뷰 대기 2개가 있다가 리뷰 대기 하나를 리뷰한다
- **THEN** 트레이 툴팁이 "D.Duck — 확인 필요 1 · 리뷰 대기 2"에서 "D.Duck — 확인 필요 1 · 리뷰 대기 1"로 바뀐다

### Requirement: 끝난 개발 작업의 후속
QA·리뷰 맡기기는 끝난 개발 작업(실패·리뷰 대기·정리 칸)에서 보여야 한다(SHALL).

#### Scenario: 리뷰 대기 칸의 개발 작업
- **WHEN** 끝난 개발 작업 카드가 리뷰 대기 칸에 있다
- **THEN** 카드에 "QA 맡기기"·"리뷰 맡기기"가 보인다
