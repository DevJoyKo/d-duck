# cloud-routine-edit Specification

## Purpose
D.Duck 안에서 claude.ai 클라우드 루틴의 켜기/끄기, 이름, 단순 일정을 안전하게 바꾸는 기능을 정의한다.

## Requirements

### Requirement: 고칠 수 있는 값

앱은 클라우드 루틴의 켜기/끄기, 이름(1–80자, 제어·bidi 문자 거부), 일정만 바꿀 수 있어야 한다(SHALL). 일정은 "한 번(미래의 날짜·시각)" 또는 "매일/매주(요일·시각)"이며 사용자 시간대로 입력받아 서버 형식으로 바꾼다. 그 밖의 cron 일정은 읽기 전용으로 보이고 claude.ai로 안내한다. 지시문·커넥터·권한·모델은 바꾸지 않는다.

#### Scenario: 한 번 실행 루틴의 날짜 옮기기
- **WHEN** 사용자가 "한 번" 루틴의 날짜·시각을 미래 시각으로 바꾸고 저장한다
- **THEN** 확인 창에 전/후 시각이 보이고, 확인하면 그 루틴의 일정만 바뀌며 목록의 다음 실행 시각이 갱신된다

#### Scenario: 복잡한 cron
- **WHEN** 루틴 일정이 매일/매주로 표현되지 않는 cron이다
- **THEN** 일정 칸은 읽기 전용이고 "claude.ai에서 고치기" 링크만 있다

#### Scenario: 과거 시각
- **WHEN** "한 번" 일정에 지금보다 이른 시각을 넣는다
- **THEN** 저장되지 않고 입력 옆에 이유가 보인다

### Requirement: 정확히 한 요청만 보낸다

앱이 만든 수정 요청(루틴 id와 바뀐 필드)과 정확히 같은 도구 입력만 실행되어야 한다(MUST). 다른 동작(만들기, 실행, 다른 루틴, 다른 필드)은 차단된다. 사용자의 Claude 설정·프로젝트 설정·MCP는 이 실행에 쓰이지 않는다.

#### Scenario: 모델이 다른 입력을 만든 경우
- **WHEN** 실행 중 도구 입력이 앱의 기대 요청과 하나라도 다르다
- **THEN** 호출은 차단되고 사용자에게 "바꾸지 못했습니다"가 보이며 루틴은 그대로다

### Requirement: 확인과 흔적

보내기 전 네이티브 확인 창이 떠야 하고(SHALL), 실행이 남긴 기록(응답 파일·세션 폴더)은 성공·실패와 관계없이 지워져야 한다(MUST). 지시문 원문은 저장하거나 로그에 남기지 않는다.

#### Scenario: 확인 취소
- **WHEN** 사용자가 확인 창에서 취소한다
- **THEN** Claude CLI는 실행되지 않는다

#### Scenario: 실패해도 정리
- **WHEN** 실행이 시간 초과·로그인 만료로 실패한다
- **THEN** 오류가 보이고 앱 작업 폴더의 Claude 기록은 남지 않는다
