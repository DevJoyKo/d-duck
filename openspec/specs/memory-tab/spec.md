# memory-tab Specification

## Purpose
Claude Code가 대화에 불러오는 자동 메모리와 지시 파일을 프로젝트별로 보고, 고치고, 잠시 끌 수 있게 한다.

## Requirements

### Requirement: 메모리 목록

메모리 탭은 자동 메모리가 있는 프로젝트를 고르게 하고(SHALL), 선택한 프로젝트의 메모리마다 이름, 설명, 종류, 수정 시각, 켜짐 여부를 보여야 한다(SHALL). MEMORY.md에는 있지만 파일이 없는 줄, 파일은 있지만 색인에 없는 메모리도 구분해 보여야 한다(SHALL).

#### Scenario: 프로젝트 메모리 보기
- **WHEN** 사용자가 홈 프로젝트를 고른다
- **THEN** MEMORY.md의 각 줄에 대응하는 메모리 5개가 이름·설명·종류와 함께 보이고, 누르면 본문이 열린다

### Requirement: 메모리 편집

사용자는 메모리 파일의 이름·설명·종류와 본문을 고칠 수 있어야 한다(SHALL). 저장은 다른 프로그램이 그사이 파일을 바꿨으면 거부되어야 하고(SHALL), 링크·하드링크 파일이나 메모리 폴더 밖 경로에는 쓰지 않아야 한다(MUST NOT). 설명을 바꾸면 MEMORY.md 색인 줄의 설명도 같이 바뀐다(SHALL).

#### Scenario: 충돌
- **WHEN** 편집하는 동안 Claude가 같은 메모리 파일을 고쳤다
- **THEN** 저장이 거부되고 "파일이 바뀌었습니다. 다시 불러오세요"가 보인다

### Requirement: 끄기와 켜기

메모리를 끄면 파일이 같은 메모리 폴더의 `.off/`로 옮겨지고 MEMORY.md에서 그 줄이 빠져야 한다(SHALL). 켜면 파일이 돌아오고 파일 이름 기준으로 색인 줄이 다시 생겨야 하며(SHALL) 줄이 중복되지 않아야 한다(MUST NOT). 꺼진 메모리는 목록에 "Claude가 쓰지 않음"으로 보인다(SHALL). 탭 맨 위의 자동 메모리 스위치는 전역 settings의 `autoMemoryEnabled`만 바꾼다(SHALL).

#### Scenario: 끄고 다시 켜기
- **WHEN** 사용자가 "Commit style" 메모리를 끄고 나중에 다시 켠다
- **THEN** 끄면 파일이 `memory/.off/`로 옮겨지고 해당 줄이 사라지며, 그사이 Claude가 MEMORY.md를 고쳐 써도 켜면 그 메모리의 줄이 한 번만 다시 생긴다

### Requirement: 지시 파일

메모리 탭은 선택한 프로젝트에 적용되는 CLAUDE.md 계열 파일을 경로·크기·git 추적 여부와 함께 읽기 전용으로 보여 주고(SHALL) "편집기에서 열기"를 제공해야 한다(SHALL). 앱 안에서 고치지 않는다.

#### Scenario: 프로젝트 지시 보기
- **WHEN** 사용자가 dev_team을 고르고 지시 파일을 연다
- **THEN** CLAUDE.md의 경로와 내용이 읽기 전용으로 보이고 "편집기에서 열기"를 누르면 기본 편집기로 열린다

### Requirement: 비밀값 경고

메모리나 지시 파일에 비밀값처럼 보이는 문자열이 있으면 경고 배지를 보여야 한다(SHALL). 앱은 메모리 본문을 DB나 로그에 남기지 않는다(MUST NOT).

#### Scenario: 토큰이 적힌 메모리
- **WHEN** 메모리 본문에 API 키 모양 문자열이 있다
- **THEN** 목록과 편집기에 "비밀값처럼 보이는 내용" 경고가 보인다
