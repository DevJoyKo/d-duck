# local-agent-tasks Specification

## Purpose
이 기기에서 실행 중인 Claude Code 세션의 상태를 보여주고, 새 백그라운드 작업을 지시하며, 로그 확인·중지·터미널 연결과 입력 대기 알림을 제공하는 로컬 작업 관제 기능을 정의한다.

## Requirements

### Requirement: 세션 상태 목록
작업 탭은 이 기기의 Claude 세션(대화형·백그라운드)을 이름, 작업 디렉터리, 종류, 상태, 시작 시각과 함께 나열해야 한다(SHALL). 완료·실패·중지된 백그라운드 세션도 앱이 그 종료 상태를 처음 관측한 때부터 24시간 동안 포함해야 한다(SHALL). 목록은 창이 보일 때 5초 이하, 숨겨져 있을 때 15초 이하 주기로 갱신해야 한다(SHALL).

#### Scenario: 끝난 백그라운드 세션
- **WHEN** 앱이 백그라운드 세션의 완료를 관측한 지 1시간이 지났다
- **THEN** 그 세션은 "완료" 열에 완료 상태로 계속 표시된다

#### Scenario: 상태 필드 누락
- **WHEN** CLI가 반환한 세션 항목에 state 필드가 없고 status만 있다
- **THEN** status 값(busy→작업 중, waiting→입력 대기, idle→대기)으로 상태를 정해 표시하고 오류를 내지 않는다

### Requirement: 상태 보드
작업 화면은 세션을 진행 순서대로 "대기 중"(쉬는 세션), "진행 중"(작업 중), "검토 필요"(답을 기다리거나 실패), "완료"(완료·중지) 네 열로 보여야 한다(SHALL). 열 안에서는 시작 시각 최신순으로 정렬하고(SHALL), 답을 기다리는 세션이 있으면 그 카드와 열 머리를 노란색으로 강조해야 한다(SHALL).

#### Scenario: 상태 열
- **WHEN** 세션 A는 입력 대기, B는 작업 중, C는 완료, D는 쉬는 중, E는 실패 상태다
- **THEN** D는 "대기 중", B는 "진행 중", A와 E는 "검토 필요", C는 "완료" 열에 표시되고, A 카드만 노란색으로 강조된다

### Requirement: 세션 종류별 조작 범위
로그 보기와 중지는 백그라운드 세션 ID가 있는 세션에서만 활성화해야 한다(SHALL). 터미널 열기와 강제 종료는 모든 세션에서 쓸 수 있어야 한다(SHALL). 대화형 세션에서는 터미널 열기가 그 세션의 작업 폴더에서 새 터미널을 여는 동작이어야 하고, 그 차이를 안내해야 한다(SHALL).

#### Scenario: 대화형 세션 선택
- **WHEN** 사용자가 다른 터미널에서 실행 중인 대화형 세션을 선택한다
- **THEN** "이 폴더에서 터미널 열기"와 "강제 종료"를 쓸 수 있고, 로그와 중지는 보이지 않으며 안내 문구가 표시된다

### Requirement: 세션 강제 종료
사용자는 목록의 모든 세션을 강제 종료할 수 있어야 한다(SHALL). 앱은 종료 직전에 그 pid가 현재 사용자 소유의 `claude` 실행 파일인지 다시 확인해야 하며(SHALL), 아니면 종료하지 않아야 한다(MUST NOT). 백그라운드 세션은 먼저 정상 중지를 시도하고, 대화형 세션은 백엔드의 네이티브 확인 창으로 승인받은 뒤 SIGTERM, 3초 안에 끝나지 않으면 SIGKILL을 보내야 한다(SHALL).

#### Scenario: 응답 없는 작업 강제 종료
- **WHEN** 사용자가 진행 중인 세션에서 "강제 종료"를 두 번 확인한다
- **THEN** 세션 프로세스가 끝나고, 다음 갱신 주기에 목록에서 상태가 바뀐다

#### Scenario: 재사용된 pid
- **WHEN** 목록의 pid가 이미 다른 프로그램에 재사용되었다
- **THEN** 앱은 그 프로세스에 신호를 보내지 않고 "종료하지 못했습니다" 오류를 표시한다

### Requirement: 새 백그라운드 작업 실행
사용자는 작업 디렉터리, 프롬프트, 작업 이름(선택), 권한 모드(선택)를 지정해 새 백그라운드 작업을 실행할 수 있어야 한다(SHALL). 권한 모드는 CLI가 허용하는 값(acceptEdits, auto, bypassPermissions, manual, dontAsk, plan) 중에서만 고를 수 있어야 한다(SHALL). 실행에 성공하면 반환된 세션 ID의 세션이 목록에 나타나야 한다(SHALL).

#### Scenario: 정상 실행
- **WHEN** 사용자가 존재하는 디렉터리와 프롬프트를 입력하고 "실행"을 누른다
- **THEN** 백그라운드 작업이 시작되고, 10초 이내에 해당 세션이 "작업 중" 그룹에 나타난다

#### Scenario: 옵션처럼 보이는 프롬프트
- **WHEN** 프롬프트가 `--dangerously-skip-permissions`나 `-p x`처럼 `-`로 시작한다
- **THEN** 그 값은 CLI 옵션이 아닌 프롬프트 텍스트로만 전달된다

#### Scenario: 신뢰되지 않은 작업 디렉터리
- **WHEN** 지정한 디렉터리가 Claude에서 아직 신뢰(trust)되지 않아 CLI가 실패한다
- **THEN** "이 디렉터리에서 claude를 한 번 실행해 신뢰를 승인하세요" 안내와 CLI 오류 메시지를 표시한다

#### Scenario: CLI 실행 실패
- **WHEN** CLI가 0이 아닌 종료 코드로 끝난다
- **THEN** 종료 코드와 오류 출력의 마지막 부분을 화면에 표시한다

### Requirement: 실행 입력 검증
앱은 실행 전에 입력을 검증하고, 위반 시 실행하지 않고 오류를 표시해야 한다(SHALL). 디렉터리는 존재하는 디렉터리여야 하고, 작업 이름은 1~64자로 `-`로 시작하지 않으며 제어문자가 없어야 하고, 프롬프트는 1바이트 이상 100KB 이하여야 한다.

#### Scenario: 잘못된 디렉터리
- **WHEN** 존재하지 않는 디렉터리를 지정한다
- **THEN** 실행하지 않고 "디렉터리를 찾을 수 없음" 오류를 표시한다

#### Scenario: 잘못된 이름
- **WHEN** 작업 이름이 `--force`이다
- **THEN** 실행하지 않고 이름 규칙 오류를 표시한다

### Requirement: 위험 권한 모드 확인
권한 모드가 bypassPermissions 또는 auto이면, 실행 전에 앱 백엔드가 띄우는 네이티브 확인 대화상자에서 사용자의 승인을 받아야 한다(SHALL). 화면(웹뷰) 쪽의 확인 여부는 신뢰하지 않아야 한다(MUST NOT). 앱은 권한 확인을 끄는 CLI 플래그를 어떤 경로로도 추가하지 않고, 임의 셸 명령 실행 기능을 제공하지 않아야 한다(MUST NOT).

#### Scenario: 위험 모드 선택
- **WHEN** 사용자가 bypassPermissions 모드를 선택하고 "실행"을 누른다
- **THEN** 위험을 설명하는 네이티브 확인 대화상자가 나타나고, 승인해야만 실행된다

#### Scenario: 화면 우회 시도
- **WHEN** 웹뷰에서 실행 명령을 직접 호출해 위험 모드로 실행을 요청한다
- **THEN** 백엔드가 네이티브 확인 대화상자를 띄우고, 거부하면 실행하지 않는다

### Requirement: 로그 보기
사용자는 백그라운드 세션을 선택해 그 세션의 최근 터미널 화면을 볼 수 있어야 한다(SHALL). 작업 중인 세션의 화면은 2초 이하 주기로 갱신되어야 한다(SHALL). 로그 내용은 HTML로 해석되지 않는 터미널 렌더러로만 표시하고(SHALL), 디스크에 저장하지 않아야 한다(MUST NOT).

#### Scenario: 실행 중 로그
- **WHEN** 사용자가 작업 중인 백그라운드 세션의 로그를 연다
- **THEN** 터미널에서 보이는 것과 같은 최근 화면이 표시되고, 2초 이내에 최신 화면으로 바뀐다

#### Scenario: HTML 주입
- **WHEN** 로그 출력에 `<img src=x onerror=alert(1)>` 문자열이 들어 있다
- **THEN** 그 문자열이 글자 그대로 표시되고 스크립트는 실행되지 않는다

### Requirement: 작업 중지
사용자는 백그라운드 세션을 중지할 수 있어야 한다(SHALL). 중지 전에 확인을 받아야 하며(SHALL), 중지 후 세션 상태는 중지로 바뀌어야 한다(SHALL). 목록에서 세션을 삭제하는 기능은 제공하지 않는다.

#### Scenario: 중지
- **WHEN** 사용자가 작업 중인 백그라운드 세션에서 "중지"를 누르고 확인한다
- **THEN** 다음 갱신 주기 안에 해당 세션이 "완료" 열에 중지 상태로 표시된다

### Requirement: 터미널 열기
사용자는 백그라운드 세션을 선택해 그 세션에 연결된 터미널을 열 수 있어야 하며(SHALL), 대화형 세션은 그 작업 폴더에서 터미널을 열 수 있어야 한다(SHALL). 입력 대기 세션에 응답하는 방법은 이 터미널 연결로 제공한다. 터미널 앱을 제어할 수 없으면(권한 거부 등) 연결 명령을 복사할 수 있게 표시해야 한다(SHALL).

#### Scenario: 입력 대기 세션 응답
- **WHEN** 사용자가 입력 대기 백그라운드 세션에서 "터미널에서 열기"를 누른다
- **THEN** 기본 터미널 앱이 열리고 해당 세션에 연결된다

#### Scenario: 터미널 제어 권한 거부
- **WHEN** macOS가 터미널 제어(Automation) 권한을 거부한다
- **THEN** 권한 안내와 함께 `claude attach <id>` 명령을 복사하는 버튼이 표시된다

### Requirement: 입력 대기 알림
세션 상태가 입력 대기로 바뀌면 OS 알림을 한 번 보내야 한다(SHALL). 알림 본문은 세션 이름과 고정된 안내 문구만 담아야 한다(SHALL). 같은 세션이 계속 입력 대기로 남아 있으면 다시 보내지 않아야 한다(MUST NOT). 알림은 설정에서 끌 수 있어야 한다(SHALL).

#### Scenario: 대기 전환 알림
- **WHEN** 작업 중이던 세션이 입력 대기로 바뀐다
- **THEN** 세션 이름을 담은 OS 알림이 한 번 표시된다

#### Scenario: 알림 끄기
- **WHEN** 설정에서 입력 대기 알림을 끈 상태로 세션이 입력 대기로 바뀐다
- **THEN** OS 알림은 표시되지 않고 목록과 트레이 표시만 바뀐다

### Requirement: 트레이의 입력 대기 표시
입력 대기 세션이 하나 이상이면 트레이 아이콘에 개수를 표시하고(SHALL), 트레이 메뉴에 입력 대기 세션 목록을 보여야 한다(SHALL). 목록 항목을 누르면 앱 창이 열리고 그 세션이 선택되어야 한다(SHALL).

#### Scenario: 트레이에서 세션 열기
- **WHEN** 입력 대기 세션 2개가 있고 사용자가 트레이 메뉴의 첫 항목을 누른다
- **THEN** 트레이에 "2"가 표시되어 있고, 앱 창이 열리며 그 세션이 선택된다

### Requirement: 기본 작업 폴더
사용자는 설정에서 기본 작업 폴더를 네이티브 폴더 선택 창으로 지정할 수 있어야 한다(SHALL). 새 작업 창은 그 폴더를 미리 채워야 하며(SHALL), 작업마다 다른 폴더를 고르거나 기본 폴더로 되돌릴 수 있어야 한다(SHALL).

#### Scenario: 기본 폴더 미리 채움
- **WHEN** 기본 작업 폴더가 `/w/app`으로 설정된 상태에서 "새 작업"을 연다
- **THEN** 작업 폴더 칸에 `/w/app`이 채워져 있고, 다른 폴더를 골라도 다음 새 작업은 다시 `/w/app`으로 시작한다

### Requirement: 처음 지시 보기
작업 보드의 각 카드는 그 세션의 처음 지시를 두 줄까지 보여야 하고(SHALL), 상세 패널은 전체(최대 4,000자)를 보여야 한다(SHALL). 처음 지시는 요청할 때마다 세션 기록에서 읽어 화면에만 표시하고, 저장하지 않아야 한다(MUST NOT).

#### Scenario: 카드의 처음 지시
- **WHEN** 보드에 "auth 테스트를 고쳐 줘"로 시작한 세션이 있다
- **THEN** 그 카드에 지시의 앞부분이 보이고, 카드를 열면 지시 전체가 보인다

### Requirement: 폴더 신뢰 확인 후 바로 시작
새 작업의 폴더를 Claude가 아직 신뢰하지 않으면, 앱은 실패로 끝내지 않고 그 자리에서 신뢰 확인을 제안해야 한다(SHALL). 사용자가 승인하면 그 폴더에서 Claude를 터미널로 열어 신뢰 확인을 받게 하고, Claude 설정에 신뢰가 기록되면 같은 작업을 자동으로 다시 시작해야 한다(SHALL). 앱은 Claude 설정 파일을 읽기만 하고 고치지 않아야 한다(MUST NOT).

#### Scenario: 신뢰되지 않은 폴더에서 시작
- **WHEN** 사용자가 신뢰되지 않은 폴더로 작업을 시작하고, 확인 창에서 "터미널에서 신뢰하기"를 고른 뒤 터미널에서 신뢰를 승인한다
- **THEN** 3분 안에 승인하면 작업이 자동으로 시작되어 '진행 중'에 나타난다

#### Scenario: 신뢰를 거절
- **WHEN** 사용자가 확인 창에서 "취소"를 고른다
- **THEN** 작업은 시작되지 않고 "이 디렉터리에서 claude를 한 번 실행해 신뢰를 승인하세요" 안내가 표시된다
