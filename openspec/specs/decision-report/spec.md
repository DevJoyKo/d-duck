## Requirements

### Requirement: 전역 설정
설정에는 "작업 보고서" 켜기/끄기가 있어야 하며(SHALL) 기본값은 켬이다(SHALL). 설명은 한 줄이다(SHALL). 켜져 있으면 D.Duck이 시작하는 모든 로컬 작업에 보고서 지시와 보고서 폴더 접근이 붙어야 하고(SHALL), 꺼져 있으면 붙지 않아야 한다(MUST NOT). 새 작업 폼은 전역 값을 기본으로 한 "이번 작업 보고서" 체크를 보여야 한다(SHALL).

#### Scenario: 끈 상태
- **WHEN** 사용자가 설정에서 작업 보고서를 끄고 새 작업을 시작한다
- **THEN** 실행 인자에 보고서 지시와 보고서 폴더가 없고 작업 상세에 보고서가 나오지 않는다

### Requirement: 보고서 작성 지시
지시는 앱 데이터 아래 작업별 폴더의 `report.json` 경로를 알려 주고, 수행 내용·blocked 기록·결정(선택지, 고른 것, 이유, 되돌리기 난이도, 묻지 않고 가정했는지, 합의와 다른지)·완료 기준 대조·레퍼런스를 정해진 JSON으로 **진행하며 갱신**하라고 요구해야 한다(SHALL). 시크릿·환경변수 값·대화 원문 인용 금지를 포함해야 한다(SHALL). 보고서 폴더는 저장소 밖이어야 한다(SHALL).

#### Scenario: 중간에 멈춘 작업
- **WHEN** 작업이 중간에 중단되었다
- **THEN** 그때까지 갱신된 보고서가 "진행 중 상태로 멈춤"과 함께 보인다

### Requirement: 보고서 보기
작업 상세의 보고서는 위에서부터 ① 위임 내용(합의) ② 완료 기준 대조 ③ 주의 항목 ④ 흐름 ⑤ 결정·blocked·레퍼런스 표 순서로 보여야 한다(SHALL). ①은 에이전트 출력이 아니라 앱이 시작할 때 가진 브리프·작업 유형·권한 모드로 채워야 한다(SHALL). ③에는 되돌리기 어려운 결정, 묻지 않고 가정한 결정, 합의와 다른 결정, 사용자가 필요한 blocked가 맨 위에 모여야 한다(SHALL). 형식이 틀리거나 1MB를 넘으면 자르지 않고 "형식 오류"를 보여야 한다(SHALL). 끝났는데 파일이 없으면 "보고서 없음"을 보여야 한다(SHALL). 앱은 보고서 내용을 DB·로그에 저장하지 않는다(MUST NOT).

#### Scenario: 합의 확인
- **WHEN** 사용자가 끝난 작업의 보고서를 연다
- **THEN** 맨 위에 시작할 때의 목표·범위 밖·제약·완료 기준이 보이고, 그 아래 완료 기준마다 ✓/△/✕와 근거가 보인다

#### Scenario: 주의 먼저
- **WHEN** 에이전트가 묻지 않고 가정한 결정 1개와 사용자가 필요한 blocked 1개를 기록했다
- **THEN** 두 항목이 "주의" 칩으로 보고서 위쪽에 먼저 보인다
