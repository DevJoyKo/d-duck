# app-language Specification

## Purpose
앱 화면과 앱이 내보내는 모든 사용자용 문구(트레이·알림·확인 창·오류)를 사용자가 고른 언어(한국어·영어)로 보여 주고, 날짜·숫자 형식과 Claude 응답 언어도 그 언어를 따르게 한다.

## Requirements

### Requirement: 언어 선택
설정에 "언어" 항목이 있어야 하며 선택지는 "시스템 언어 따름"·"한국어"·"English" 세 가지여야 한다(SHALL). 기본값은 "시스템 언어 따름"이어야 한다(SHALL). 시스템 언어 따름일 때 OS 기본 언어가 한국어(`ko`로 시작)면 한국어, 그 밖에는 영어를 써야 한다(SHALL). 선택은 앱 데이터에 저장되어 재시작 후에도 유지되어야 하며(SHALL), 각 선택지 이름은 현재 언어와 상관없이 그 언어 자체로 표시해야 한다(SHALL, 예: 영어 화면에서도 "한국어"). 설정 페이지 외에 사이드바 상단 테마 버튼 옆에 빠른 언어 전환 메뉴(한국어·English·시스템 언어 따름)가 있어야 하며(SHALL), 같은 저장 값을 공유하고 고르면 바로 적용되어야 한다(SHALL). 그 버튼의 접근 이름은 현재 언어로 보여야 한다(SHALL, "언어 바꾸기"/"Change language").

#### Scenario: 처음 실행, 영어 OS
- **WHEN** 언어를 고른 적이 없고 OS 기본 언어가 en-US다
- **THEN** 사이드바·설정·빈 상태 문구가 영어로 보이고, 설정의 언어 값은 "System language"다

#### Scenario: 처음 실행, 한국어 OS
- **WHEN** 언어를 고른 적이 없고 OS 기본 언어가 ko-KR이다
- **THEN** 지금과 같은 한국어 화면이 보인다

#### Scenario: 사이드바 빠른 전환
- **WHEN** 한국어 화면에서 사이드바의 "언어 바꾸기" 메뉴를 열고 "English"를 고른다
- **THEN** 화면이 바로 영어로 바뀌고 버튼 이름은 "Change language"가 되며, 설정 페이지의 언어 값도 English다

#### Scenario: 직접 고름 유지
- **WHEN** 한국어 OS에서 "English"를 고르고 앱을 종료한 뒤 다시 연다
- **THEN** 첫 화면부터 영어로 보인다

### Requirement: 바로 적용
언어를 바꾸면 앱을 다시 시작하지 않고 열려 있는 화면, 트레이 메뉴, 이후의 OS 알림과 확인 창이 새 언어로 바뀌어야 한다(SHALL). 바꾸는 동안 입력 중인 작업 초안과 열린 시트의 상태는 유지되어야 한다(SHALL).

#### Scenario: 초안 유지
- **WHEN** 작업 시키기 창에 목표를 적은 채 설정에서 언어를 English로 바꾸고 돌아온다
- **THEN** 창의 라벨과 버튼은 영어이고 적어 둔 목표는 그대로다

#### Scenario: 트레이
- **WHEN** 언어를 English로 바꾼다
- **THEN** 트레이 메뉴가 "Open window"·"Quit" 등 영어로 바로 바뀐다

### Requirement: 화면 문구 카탈로그
모든 화면 문구는 언어별 메시지 카탈로그에서 와야 한다(SHALL). 한국어와 영어 카탈로그는 같은 키 집합과 같은 파라미터 이름을 가져야 하며(SHALL), 하나라도 다르면 테스트가 실패해야 한다(SHALL). 화면 소스와 Rust의 사용자용 문구 경로에 카탈로그(또는 Rust 메시지 테이블)를 거치지 않은 한글 문구가 있으면 검사가 실패해야 한다(SHALL, 주석·테스트·mock 데이터·로그 전용 문자열·허용 목록 제외). 수·개수가 들어간 영어 문구는 단수·복수를 구분해야 한다(SHALL).

#### Scenario: 키 누락
- **WHEN** 개발자가 한국어 카탈로그에만 새 키를 넣는다
- **THEN** 카탈로그 완전성 테스트가 그 키 이름과 함께 실패한다

#### Scenario: 복수형
- **WHEN** 영어에서 리뷰 전 작업이 1개, 3개다
- **THEN** 배지 접근 이름이 각각 "1 task to review", "3 tasks to review"다

### Requirement: 사용자 데이터는 번역하지 않음
작업 이름, 목표, 브리프, 에이전트·스킬·플러그인 이름, 파일 경로, 세션 제목, Claude가 쓴 보고서 본문처럼 사용자나 Claude가 만든 내용은 언어 설정과 상관없이 원문 그대로 보여야 한다(SHALL). 앱이 붙이는 라벨만 번역한다.

#### Scenario: 한국어 목표, 영어 화면
- **WHEN** 영어 화면에서 목표가 "로그인 버그 고치기"인 작업 카드를 본다
- **THEN** 카드 라벨은 영어이고 목표 줄은 "로그인 버그 고치기" 그대로다

### Requirement: 앱 기본 제공 데이터
앱이 기본으로 제공하는 팀 기본값(작업 유형·역할 이름과 설명, 팀 규칙)과 권한 목록의 라벨·설명은 두 언어로 제공되어 현재 언어로 보여야 한다(SHALL). 사용자가 이름이나 설명을 바꾼 항목은 사용자 데이터로 보고 번역하지 않아야 한다(SHALL). 기본값에 들어 있는 Claude용 고정 지시는 작업을 시작할 때의 언어 판으로 보내야 한다(SHALL).

#### Scenario: 기본 유형 이름
- **WHEN** 영어 화면에서 이름을 바꾸지 않은 기본 작업 유형과 이름을 "백엔드 담당"으로 바꾼 유형을 본다
- **THEN** 앞의 것은 영어 이름이고, 뒤의 것은 "백엔드 담당" 그대로다

#### Scenario: 권한 라벨
- **WHEN** 영어 화면에서 에이전트 권한 목록을 연다
- **THEN** 권한 라벨과 설명이 영어다

### Requirement: 백엔드가 주는 사용자 문구
백엔드가 화면에 보여 줄 오류·거절 이유·안내를 보낼 때는 언어와 무관한 코드와 파라미터로 보내야 하며(SHALL), 화면이 현재 언어로 바꿔 보여야 한다(SHALL). 화면이 모르는 코드면 백엔드가 함께 보낸 현재 언어 문장을 보여야 한다(SHALL). 백엔드가 만든 표시용 문장(배너·상태 줄 등 오류가 아닌 안내)도 같은 방식으로 보내야 한다(SHALL). 파라미터는 코드마다 정해진 형태(숫자, 정해진 값, 정리된 이름)여야 하며 transcript 원문·자격증명·프롬프트 원문이 들어가지 않아야 하고(MUST NOT), URL은 호스트만, 경로는 마지막 이름만 실어야 한다(SHALL). 파라미터 값은 마크업으로 해석되지 않고 글자로만 보여야 한다(SHALL).

#### Scenario: 시작 거절
- **WHEN** 영어 화면에서 로컬 작업만 프로젝트에 bypass 모드로 작업을 시작해 백엔드가 거절한다
- **THEN** 하단에 영어 거절 이유와 영어 고치기 링크가 보인다

#### Scenario: URL 노출 없음
- **WHEN** 원격 주소가 `https://user:token@example.com/x.git`인 로컬만 프로젝트의 push 거절 문구가 나온다
- **THEN** 화면과 로그에는 `example.com`만 보이고 `user:token`은 어디에도 없다

#### Scenario: 모르는 코드
- **WHEN** 화면 카탈로그에 없는 새 오류 코드가 온다
- **THEN** 백엔드가 같이 보낸 현재 언어 문장이 보이고 코드 이름만 보이지 않는다

### Requirement: OS 표면 문구
트레이 메뉴, OS 알림(입력 대기·작업 끝·한도 도달), 휴대폰 원격 알림, 네이티브 확인 창과 파일 선택 창 제목은 저장된 언어로 만들어야 한다(SHALL). 알림에 들어가는 작업 이름은 지금처럼 제어 문자를 없애고 64자로 줄여야 한다(SHALL). 문서의 언어 속성(`<html lang>`)은 현재 화면 언어와 같아야 한다(SHALL). 저장된 값이 "시스템 언어 따름"이면 같은 규칙(ko → 한국어, 그 밖 → 영어)을 따른다(SHALL).

#### Scenario: 알림
- **WHEN** 언어가 English이고 작업이 입력을 기다린다
- **THEN** OS 알림 제목과 본문이 영어다(작업 이름은 원문)

### Requirement: 날짜·숫자 형식
날짜·시간·상대 시간("3분 전"/"3 min ago")·숫자·비용 표시는 현재 언어의 형식을 따라야 한다(SHALL). 루틴 시간 고르기처럼 24시간제로 정한 곳은 언어와 상관없이 24시간제를 유지한다(SHALL).

#### Scenario: 날짜
- **WHEN** 2026-11-09 20:19(로컬)를 목록 시각으로 한국어와 영어 화면에서 본다
- **THEN** 한국어는 `ko-KR` {month:2-digit, day:2-digit, hour:2-digit, minute:2-digit} 결과("11. 09. 오후 08:19"), 영어는 `en-US` 같은 옵션 결과("11/09, 08:19 PM")로 보인다 — 두 값 모두 `Intl.DateTimeFormat` 실측값으로 테스트에 고정한다

#### Scenario: 백엔드가 만든 시각 문장
- **WHEN** 사용량 한도 배너가 리셋 시각을 보여 준다
- **THEN** 시각은 화면이 현재 언어 형식으로 만든 것이고, 백엔드가 만든 "오전/오후" 문장이 영어 화면에 나오지 않는다

### Requirement: Claude 응답 언어
앱이 Claude에게 보내는 고정 지시(요구사항 다듬기, 그릴링 질문, 보고서 작성 지시, 리뷰·QA 근거 요구)는 사람이 읽는 출력(질문·요약·보고서 본문)을 앱 언어로 쓰라고 요청해야 한다(SHALL). 보고서 JSON의 키와 판정 값 같은 기계용 필드는 언어와 무관해야 한다(SHALL). 이미 시작한 작업은 시작할 때의 언어를 유지한다(SHALL).

#### Scenario: 영어 그릴링
- **WHEN** 영어 화면에서 질문 만들기를 누른다
- **THEN** 질문과 선택지가 영어로 오고, 사용자가 한국어로 쓴 목표는 그대로 인용된다

### Requirement: 언어별 문구 규칙
한국어 카탈로그는 기존 문구 규칙(해요체, 항목당 한 줄, "리뷰" 용어, "전역")을 따라야 하고(SHALL), 영어 카탈로그는 평이한 문장, sentence case, 항목당 한 줄, 같은 개념에 같은 단어(review, global)를 써야 한다(SHALL). 두 규칙 모두 자동 검사가 있어야 한다(SHALL).

#### Scenario: 한국어 규칙 유지
- **WHEN** 한국어 카탈로그에 "검토 대기"나 "~합니다"로 끝나는 문구가 들어간다
- **THEN** 문구 규칙 테스트가 실패한다

### Requirement: 영어 레이아웃
영어 화면은 900px 창 폭과 1440px에서 라이트·다크 모두 버튼·탭·배지 문구가 잘리거나 겹치지 않아야 한다(SHALL). 공간이 모자라면 말줄임과 전체 문구 툴팁을 써야 한다(SHALL).

#### Scenario: 좁은 창
- **WHEN** 영어로 900px 창에서 작업 보드와 작업 시키기 하단을 본다
- **THEN** 칸 제목과 "Start task" 버튼이 한 줄에 보이고 겹치지 않는다
