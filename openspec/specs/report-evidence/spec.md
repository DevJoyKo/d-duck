## Requirements

### Requirement: 완료 기준마다 근거 항목
보고서 형식은 완료 기준마다 사람이 읽는 한 줄과 근거 항목 목록을 가져야 한다(SHALL). 근거 종류는 스크린샷(png·jpg), 테스트 리포트(JUnit XML 또는 D.Duck 테스트 요약 JSON), 명령(명령·종료 코드·출력 파일), 파일(저장소 상대 경로와 줄 범위) 넷이어야 한다(SHALL). 원격 링크 종류는 없어야 하며(MUST NOT), 앱은 근거를 위해 네트워크에서 아무것도 가져오지 않아야 한다(MUST NOT). 기준마다 6개, 보고서 전체 60개를 넘으면 형식 오류여야 한다(SHALL).

#### Scenario: 근거가 있는 기준
- **WHEN** 기준 "목록 화면이 다크 모드에서 읽힌다"가 충족이고 근거로 스크린샷 1개와 vitest JUnit 1개가 있다
- **THEN** 보고서 기준 줄에 ✓와 근거 칩 2개("스크린샷 list-dark.png", "테스트 vitest.xml")가 보인다

### Requirement: 근거 파일의 위치
스크린샷·테스트 리포트·명령 출력 파일은 그 작업 보고서 폴더의 `evidence/` 바로 아래에만 있어야 한다(SHALL). 이름이 영문·숫자·`.`·`-`·`_` 80자를 벗어나거나 하위 폴더·`..`·절대 경로를 쓰면 형식 오류여야 한다(SHALL). 파일 근거는 작업 폴더 안의 일반 파일이고 줄 범위가 파일 안에 있을 때만 유효해야 하며(SHALL), `.git` 아래와 작업 폴더 밖은 유효하지 않아야 한다(SHALL).

#### Scenario: 폴더 밖 경로
- **WHEN** 근거 경로가 `../other/shot.png`다
- **THEN** 그 보고서는 형식 오류로 보인다

### Requirement: 근거 파일의 안전 읽기
앱은 링크·하드 링크·일반 파일이 아닌 근거와 열린 파일의 실제 위치가 다른 근거를 읽지 않아야 한다(MUST NOT). 크기(스크린샷 5MB, 테스트 리포트 2MB, 명령 출력 256KB, 보고서 폴더 50MB)나 `evidence/` 항목 100개를 넘으면 유효하지 않아야 한다(SHALL). 그림은 PNG 청크·JPEG 세그먼트 구조가 온전하고 8000px·4천만 픽셀 이하일 때만 받아야 하며(SHALL), 형식은 확장자가 아니라 내용 구조로 판단해야 한다(SHALL). 근거 경로·이름·내용은 DB·로그·오류 문구에 남기지 않아야 하고(MUST NOT), 웹뷰에는 파일 이름의 마지막 부분만 라벨로 보내야 한다(SHALL).

#### Scenario: 링크로 바꿔치기
- **WHEN** `evidence/shot.png`가 `~/.ssh/id_rsa`를 가리키는 링크다
- **THEN** 그 근거는 "읽지 않았어요(안전하지 않은 파일)"로 보이고 파일 내용은 읽히지 않는다

#### Scenario: 확장자만 png
- **WHEN** `evidence/x.png`의 실제 내용이 HTML이다
- **THEN** 그 근거는 "형식이 맞지 않아요"로 보이고 유효한 근거로 세지 않는다

#### Scenario: 잘린 JPEG
- **WHEN** JPEG의 세그먼트 길이가 파일 끝을 넘는다
- **THEN** 그 근거는 "형식이 맞지 않아요"다

### Requirement: 근거 없음 판정
충족 또는 일부 충족인 기준에 그 역할에서 유효한 종류의 근거가 하나도 없으면 "근거 없음"으로 보여야 하고(SHALL) 충족 개수에 들어가지 않아야 한다(MUST NOT). 못 했어요인 기준에는 근거를 요구하지 않아야 한다(SHALL). 근거 없음은 판정 줄, 기준 줄, 먼저 확인할 것, 리뷰 카드에 보여야 하며(SHALL), 근거 없음이 있으면 판정 줄은 "합의대로 마쳤어요"가 아니어야 한다(MUST NOT).

#### Scenario: 개발 작업의 근거 없음
- **WHEN** 끝난 개발 작업의 기준 3개가 모두 충족인데 그중 1개에 근거가 없다
- **THEN** 판정 줄은 주의 색 "근거 없음 1 → 확인 필요", 카드 기준 줄은 "충족 2 · 근거 없음 1"이다

#### Scenario: 테스트 실패와 충족이 어긋남
- **WHEN** 충족으로 적힌 기준의 JUnit 근거에 실패가 2개 있다
- **THEN** 먼저 확인할 것에 "테스트 실패 2" 칩이 그 기준을 가리킨다

### Requirement: 리뷰·QA의 엄격한 판정
리뷰·QA 유형 작업의 근거 없음은 위험(빨강) 색이고 판정 줄에서 "못 했어요" 바로 다음이어야 하며(SHALL), 그 밖의 유형은 주의 색이고 "일부 충족" 다음이어야 한다(SHALL). 리뷰 유형은 파일 근거만 유효로 세야 하고(SHALL), QA 유형은 스크린샷·테스트 리포트·명령 근거만 유효로 세야 한다(SHALL). QA 작업이 끝났는데 유효한 테스트 리포트가 없으면 빨간 "테스트 리포트 없음"이 보여야 한다(SHALL).

#### Scenario: QA 작업의 파일 근거
- **WHEN** 끝난 QA 작업의 기준 2개가 충족이고 그중 1개는 파일 근거만 있다
- **THEN** 판정 줄은 빨간 "근거 없음 1 → 확인 필요"로 시작한다

#### Scenario: 리뷰 작업의 파일 근거
- **WHEN** 끝난 리뷰 작업의 기준 2개가 충족이고 둘 다 파일:줄 근거가 있다
- **THEN** 근거 없음이 없고 각 기준에 "파일 src/a.ts:10–42" 칩이 있다

#### Scenario: QA 테스트 리포트 없음
- **WHEN** 끝난 QA 작업 보고서의 모든 근거가 스크린샷이다
- **THEN** 판정 줄에 빨간 "테스트 리포트 없음"이 있고 "합의대로 마쳤어요"가 아니다

### Requirement: 지울 수 없는 근거 규칙
리뷰·QA 유형 작업에는 근거 규칙이 "[필수]" 줄로 시스템 지시에 붙어야 하고(SHALL), 팀 설정에서 지우거나 바꾸거나 덧붙일 수 없어야 하며(MUST NOT), 역할 지시를 바꾸거나 내 에이전트를 써도 빠지지 않아야 한다(SHALL). 팀 설정의 리뷰·QA 유형 편집에는 자물쇠와 "필수 · 근거 규칙" 읽기 전용 상자, 한 줄 "리뷰·QA는 근거 파일을 꼭 남겨요"가 보여야 한다(SHALL). 사용자가 추가한 유형에는 붙지 않아야 한다(MUST NOT).

#### Scenario: 역할 지시를 바꿔도
- **WHEN** 사용자가 QA 유형의 역할 지시를 통째로 바꾸고 QA 작업을 시작한다
- **THEN** 시스템 지시에 "[필수]" 근거 규칙 줄이 그대로 있다

### Requirement: 보고서 설정과 리뷰·QA
앱은 전역 작업 보고서 설정을 따라야 한다(SHALL). 보고서가 꺼진 상태에서 리뷰·QA 작업을 Composer로 시작하려 하면 보고서 줄에 "근거를 남기려면 보고서가 필요해요"와 이번 작업만 붙이는 체크(기본 켬)를 보여야 한다(SHALL). 사용자가 끄고 시작하면 보고서 없이 시작해야 한다(SHALL). 리뷰 작업에서 원격 조작을 고르면 "원격 조작이면 근거를 남길 수 없어요"를 보여야 한다(SHALL).

#### Scenario: 보고서 설정 꺼짐
- **WHEN** 전역 작업 보고서 설정이 꺼져 있고 사용자가 Composer에서 QA 작업을 고른다
- **THEN** "근거를 남기려면 보고서가 필요해요"와 켜진 체크가 보이고, 그대로 시작하면 그 작업에만 보고서가 붙는다

### Requirement: 보고서 폴더에만 쓰는 읽기 전용 역할
쓰기 도구가 없는 역할(리뷰·보안·QA)에 보고서가 붙으면, 앱은 보고서 폴더 안 쓰기를 확인 없이 허용하고 밖 쓰기를 막는 범위에서만 쓰기 도구를 더해야 한다(SHALL). 판단할 수 없는 쓰기는 막아야 한다(SHALL). 원래 쓰기 도구가 없던 역할의 명령에 출력 옵션이나 리다이렉션이 있으면 막아야 한다(SHALL). 이 범위를 지킬 수 없는 환경이면 쓰기 도구를 더하지 않고 "이 환경에서는 보고서를 쓸 수 없어요"를 보여야 한다(SHALL).

#### Scenario: 리뷰어가 저장소를 고치려 함
- **WHEN** 보고서가 붙은 리뷰 작업(매번 확인 모드)이 저장소의 `src/a.ts`를 쓰려 한다
- **THEN** 쓰기가 막히고, 같은 작업이 보고서 폴더의 `report.json`은 확인 창 없이 쓴다

#### Scenario: git 출력 옵션
- **WHEN** 보고서가 붙은 리뷰 작업이 `git diff --output=/tmp/x`를 실행하려 한다
- **THEN** 그 명령이 막힌다

### Requirement: 근거를 남기라는 보고서 지시
모든 보고서 지시는 근거 파일을 `evidence/`에 남기는 방법을 담아야 한다(SHALL). 화면 작업은 Playwright 스크린샷만이고 Playwright가 없으면 일부 충족과 이유를 쓰라고 해야 하며(SHALL), 화면 전체 캡처 도구를 안내하지 않아야 한다(MUST NOT). 테스트는 리포트 파일(vitest·Playwright·pytest·cargo nextest JUnit, 없으면 D.Duck 테스트 요약 JSON), 명령은 명령·종료 코드·출력 파일(200줄 이내, 환경변수·토큰 출력 금지)이어야 한다(SHALL). 지시 전체는 2,000자를 넘지 않아야 한다(SHALL).

#### Scenario: 지시 내용
- **WHEN** 보고서가 붙은 개발 작업을 시작한다
- **THEN** 시스템 지시에 `evidence/` 경로, Playwright 안내, JUnit 명령 예시, "근거 없이 met yes를 쓰지 않는다"가 있고 `screencapture`는 없으며 지시는 2,000자 이하다

### Requirement: 이전 형식 보고서
근거 배열이 없는 이전 형식 보고서는 계속 읽혀야 하고(SHALL), 중립 칩 "근거 형식 이전 보고서"를 보여야 하며(SHALL), 근거 없음·테스트 리포트 없음을 계산하지 않아야 한다(MUST NOT).

#### Scenario: 업데이트 전 보고서
- **WHEN** 업데이트 전에 끝난 작업의 보고서를 연다
- **THEN** 이전과 같은 판정 줄과 "근거 형식 이전 보고서" 칩이 보이고 근거 없음 표시는 없다

### Requirement: 근거 칩과 미리보기
기준 줄 아래에는 근거 칩(종류 아이콘 + 이름)이 있어야 하고(SHALL), 유효하지 않은 근거는 흐린 칩과 이유 한 줄로 보여야 한다(SHALL). 칩을 누르면 그 기준 아래에서 미리보기가 열려야 한다(SHALL): 그림 크게 보기(Esc로 닫고 포커스 복귀), 테스트 통과·실패·건너뜀 수와 실패 이름(50개까지), 명령·종료 코드·출력 발췌(앞 80줄과 끝 120줄), 파일은 경로와 줄 범위만. 그림은 누를 때만 불러와야 한다(SHALL).

#### Scenario: 스크린샷 보기
- **WHEN** 사용자가 "스크린샷 list-dark.png" 칩을 누른다
- **THEN** 그 기준 아래에 그림이 크게 열리고, Esc를 누르면 닫히며 포커스가 칩으로 돌아간다

#### Scenario: 테스트 요약
- **WHEN** 사용자가 실패 2개가 있는 JUnit 칩을 누른다
- **THEN** "통과 48 · 실패 2 · 건너뜀 1" 표와 실패한 테스트 이름 2줄이 보인다

### Requirement: 테스트 리포트의 안전한 해석
테스트 리포트에 문서 형식 선언이나 처리 지시가 있으면 앱은 그 파일을 해석하지 않아야 하고(MUST NOT), 알 수 없는 엔티티·깊이 32·요소 20만 개를 넘으면 "형식이 맞지 않아요"여야 한다(SHALL).

#### Scenario: 엔티티 폭탄
- **WHEN** JUnit 파일에 문서 형식 선언과 엔티티 정의가 있다
- **THEN** 그 근거는 "형식이 맞지 않아요"이고 엔티티는 펼쳐지지 않는다

### Requirement: 리뷰 카드의 근거 수
리뷰 카드에는 "근거 N"(중립)과, 있으면 "근거 없음 N"이 보여야 한다(SHALL). 리뷰 탭 목록 응답에는 근거 이름·명령·설명이 없어야 한다(MUST NOT).

#### Scenario: 카드
- **WHEN** 리뷰 전 QA 작업의 보고서에 유효 근거 5개와 근거 없음 기준 1개가 있다
- **THEN** 카드에 "근거 5"와 빨간 "근거 없음 1"이 보인다

### Requirement: 근거 파일의 보관과 프라이버시
근거 파일은 이 Mac의 앱 데이터 보고서 폴더에만 있어야 하고(SHALL), 앱은 근거를 업로드·공유·자동으로 클립보드에 복사하지 않아야 한다(MUST NOT). 사용자가 작업 기록을 지우면 그 보고서 폴더를 근거째 바로 지워야 한다(SHALL). 앱은 근거를 만들거나 대화 기록에서 뽑지 않아야 한다(MUST NOT). 설정의 작업 보고서 설명에 "근거 스크린샷·테스트 리포트도 이 Mac의 앱 폴더에만 두고, 작업 기록과 함께 지워져요"가 있어야 한다(SHALL).

#### Scenario: 기록 삭제
- **WHEN** 사용자가 지난 작업에서 근거가 있는 작업 기록을 지운다
- **THEN** 그 보고서 폴더가 `evidence/`째 곧바로 지워진다

### Requirement: 첨부 보고서
에이전트는 보고서 폴더의 `attachments/` 바로 아래에 HTML 또는 Markdown 문서를 10개까지 두고 보고서에 제목과 함께 적을 수 있어야 한다(SHALL). 첨부와 `attachments/` 폴더는 근거와 같은 안전 읽기(링크·하드 링크·일반 파일 아님·실제 위치 다름 거부)를 따라야 한다(SHALL). HTML 512KB·Markdown 64KB를 넘으면 자르지 않고 거부해야 하며(SHALL), 폴더 항목 50개를 넘거나 엄격한 UTF-8이 아니면 유효하지 않아야 한다(SHALL). 첨부는 이 Mac의 보고서 폴더에만 있어야 하고, 업로드되지 않으며(MUST NOT), 작업 기록과 함께 지워져야 한다(SHALL).

#### Scenario: 리서치 첨부
- **WHEN** 리서치 작업 보고서에 `attachments/compare.html`("DB 후보 비교")이 적혀 있다
- **THEN** 보고서의 "첨부" 칸에 "DB 후보 비교" 탭이 있고 누르면 그 문서가 보인다

#### Scenario: 잘못된 인코딩
- **WHEN** 첨부 파일에 UTF-8이 아닌 바이트가 하나 있다
- **THEN** 그 탭은 흐리게 "형식이 맞지 않아요"로 보이고 내용은 그려지지 않는다

### Requirement: HTML 첨부의 안전한 그리기
HTML 첨부는 스크립트·폼·외부 이동·네트워크 없이 그려져야 한다(SHALL). 앱은 스크립트·틀·폼·메타·base·svg·이벤트 속성을 지워야 하고(SHALL), 스크립트와 네트워크를 막는 보안 정책과 격리된 틀 안에서만 보여야 한다(SHALL). 조각(`#`)이 아닌 링크는 이동하지 않게 하되 링크 글과 그 주소의 host를 글로 남겨야 한다(SHALL). 스타일 요소와 스타일 속성은 배치·글자·색만 남기고 외부 자원을 부르는 규칙(url·import·글꼴 정의 등)을 지워야 한다(SHALL). 그림은 같은 첨부 폴더의 png·jpg 또는 본문의 data URI일 때만, 근거와 같은 그림 구조 검사를 통과할 때만 보여야 하며(SHALL), 첨부 하나당 20장·합계 8천만 픽셀·참조마다 센 합계 5MB를 넘는 그림은 빠져야 한다(SHALL). 정리 결과를 다시 정리해도 같아야 한다(SHALL). 정리 뒤 내용이 없으면 "보여 드릴 내용이 없어요"여야 한다(SHALL).

#### Scenario: 스크립트가 든 첨부
- **WHEN** HTML 첨부에 `<script>`, `<img src=x onerror=…>`, `<meta http-equiv="refresh">`, 원격 그림, `<style>@import url(https://…)</style>`가 있다
- **THEN** 첨부는 글·표·색만 보이고, 스크립트가 실행되지 않으며, 네트워크 요청과 페이지 이동이 없다

#### Scenario: 출처 링크
- **WHEN** 리서치 첨부에 `<a href="https://docs.example.com/x">공식 문서</a>`가 있다
- **THEN** 문서에 "공식 문서 (docs.example.com)"이 글로 보이고, 눌러도 이동하지 않는다

#### Scenario: 같은 그림 반복
- **WHEN** 첨부가 3MB 그림 하나를 두 번 참조한다
- **THEN** 두 번째 그림은 빠지고 첫 번째만 보인다

#### Scenario: 스크립트만 있는 문서
- **WHEN** HTML 첨부의 내용이 `<script>`뿐이다
- **THEN** 그 탭은 "보여 드릴 내용이 없어요"를 보인다

### Requirement: Markdown 첨부
Markdown 첨부는 원문 HTML을 그리지 않아야 하고(MUST NOT), 64KB까지 받아야 하며(SHALL), 파이프 표(머리·정렬 줄·셀)를 표로 그려야 한다(SHALL). 그림은 같은 첨부 폴더 이름일 때만 HTML 첨부와 같은 검사·예산으로 보여야 한다(SHALL).

#### Scenario: 비교 표
- **WHEN** 설계 첨부 Markdown에 3열 5행 파이프 표가 있다
- **THEN** 첨부 칸에 3열 5행 표가 보인다

#### Scenario: 큰 Markdown
- **WHEN** Markdown 첨부가 50KB다
- **THEN** 끝까지 그려지고 잘리지 않는다

### Requirement: 첨부 보기 머리와 닫기
첨부 보기 위에는 앱이 그린 머리 "에이전트가 만든 문서 · <제목>"과 "크게 보기"·"닫기"가 문서 바깥에 늘 보여야 한다(SHALL). "크게 보기"는 같은 격리된 보기로 앱 창 전체에 열려야 한다(SHALL). 포커스가 문서 안에 있어도 "닫기"로 닫을 수 있어야 하고(SHALL), Shift+Tab으로 머리 버튼에 돌아올 수 있어야 한다(SHALL).

#### Scenario: 문서 안에 포커스
- **WHEN** 사용자가 크게 보기 안 문서를 눌러 포커스가 문서 안에 있고 Esc를 누른다
- **THEN** 문서는 그대로이고, 머리의 "닫기"가 보이며 누르면 닫히고 포커스가 "크게 보기" 버튼으로 돌아간다

### Requirement: 유형별 보고서 형태
리서치·설계·커뮤니케이션·학습 유형은 완료 기준 없이 첨부만 내도 되어야 하고(SHALL), 그때 판정 줄은 "첨부 보고서 N개"이며 막힘·결정 주의는 그 뒤에 붙어야 한다(SHALL). 기준이 없으면 근거 없음을 계산하지 않아야 하고(MUST NOT), 브리프에 완료 기준이 있으면 이 유형도 기준 대조를 해야 한다(SHALL). 개발·디자인·배포·보안·리뷰·QA와 사용자가 추가한 유형은 기준 대조가 필수이고(SHALL), 기준 없이 첨부만 내면 "기준 대조가 없어요 · 첨부 보고서 N개 → 확인이 필요해요"여야 한다(SHALL).

#### Scenario: 첨부만 낸 설계 작업
- **WHEN** 완료 기준 없는 브리프로 맡긴 설계 작업이 기준 없이 첨부 2개를 냈다
- **THEN** 판정 줄은 "첨부 보고서 2개"이고 근거 없음 표시는 없다

#### Scenario: 첨부만 낸 디자인 작업
- **WHEN** 디자인 작업이 기준 없이 첨부 1개만 냈다
- **THEN** 판정 줄은 주의 색 "기준 대조가 없어요 · 첨부 보고서 1개 → 확인이 필요해요"다

### Requirement: 첨부를 남기라는 지시와 리뷰 카드
보고서 지시는 기준 대조로 담기 어려운 결과를 첨부로 남기고, HTML은 스크립트·외부 글꼴·원격 그림 없이 파일 하나로 완결하며, 출처 주소를 글로도 적으라고 해야 한다(SHALL). 기준이 없는 리뷰 카드는 기준 미리보기 대신 첫 첨부의 제목과, 제목과 다른 첫 문단의 앞 120자를 보여야 한다(SHALL). 카드 첫 줄은 파일이 바뀌지 않으면 다시 계산하지 않아야 하고(SHALL), 목록 응답에는 그보다 긴 첨부 본문이 없어야 한다(MUST NOT).

#### Scenario: 첨부 카드
- **WHEN** 기준 없이 첨부 1개("DB 후보 비교", 첫 문단 "세 후보를 비용·운영으로 비교했어요")를 낸 리서치 작업이 리뷰 전이다
- **THEN** 카드에 "첨부 보고서 1개", "DB 후보 비교", "세 후보를 비용·운영으로 비교했어요"가 한 줄씩 보인다
