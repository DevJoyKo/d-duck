# skill-authoring Specification

## Purpose
D.Duck 안에서 Claude Code 스킬·슬래시 커맨드·워크플로를 직접 또는 Claude에게 맡겨 만들고, 만든 것을 고칠 수 있게 한다.

## Requirements

### Requirement: 직접 만들기

스킬 탭에서 종류(스킬·커맨드·워크플로), 위치(내 것 또는 알려진 프로젝트), 이름, 설명, 본문을 입력해 새 항목을 만들 수 있어야 한다(SHALL). 종류별 기본 틀이 채워져야 하고(SHALL), 같은 이름이 이미 있으면 덮어쓰지 않아야 한다(MUST NOT). 이름은 영문·숫자·`-`·`_`만, 1–64자여야 한다(SHALL).

#### Scenario: 내 커맨드 만들기
- **WHEN** 사용자가 커맨드, 내 것, 이름 `standup`, 설명을 입력하고 저장한다
- **THEN** `~/.claude/commands/standup.md`가 frontmatter와 함께 생기고 커맨드 목록에 `/standup`이 보인다

#### Scenario: 이름 충돌
- **WHEN** 이미 있는 스킬 이름으로 만들려 한다
- **THEN** 저장되지 않고 "이미 있는 이름입니다"가 보인다

### Requirement: Claude에게 만들기

사용자가 원하는 것을 쓰고 종류·위치를 고르면 D.Duck이 만들기 지침을 붙인 백그라운드 작업을 시작해야 한다(SHALL). 작업은 고른 위치 안에만 파일을 만들도록 지시받고, 작업 보드에서 추적되어야 한다(SHALL). 완료되면 새 항목이 목록에 "새로 만듦"으로 보여야 한다(SHALL).

#### Scenario: 스킬 요청
- **WHEN** 사용자가 "PR 설명을 우리 팀 형식으로 써 주는 스킬"을 요청한다
- **THEN** 작업이 시작되어 작업 보드에 보이고, 끝나면 내 스킬 목록에 새 스킬이 나타나며 바로 고칠 수 있다

### Requirement: 고치기

내 것과 프로젝트의 스킬(SKILL.md), 커맨드(.md), 워크플로(.js·.mjs)를 앱에서 열어 고칠 수 있어야 한다(SHALL). 그사이 파일이 바뀌었으면 저장을 거부해야 하고(SHALL), 링크·하드링크 파일이나 허용 폴더 밖에는 쓰지 않아야 한다(MUST NOT). 플러그인·동기화 항목은 읽기 전용이어야 한다(SHALL).

#### Scenario: 플러그인 스킬
- **WHEN** 사용자가 플러그인에 들어 있는 스킬을 연다
- **THEN** 내용은 보이지만 편집기는 읽기 전용이고 "플러그인 항목은 고칠 수 없습니다"가 보인다

### Requirement: 만들기 지침과 터미널 커맨드

앱은 기본 만들기 지침을 가지고 있어야 하며 사용자가 고칠 수 있어야 한다(SHALL). 사용자가 원하면 같은 지침을 담은 슬래시 커맨드를 내 커맨드 폴더에 설치하고 지울 수 있어야 한다(SHALL).

#### Scenario: 터미널 커맨드 설치
- **WHEN** 사용자가 "터미널에서도 쓰기"를 켜고 확인한다
- **THEN** `~/.claude/commands/dduck-new.md`가 생기고, 끄면 그 파일이 휴지통으로 간다
