## Requirements

### Requirement: 다듬기 시작
새 작업 폼은 목표가 비어 있지 않을 때 "요구사항 다듬기"를 제공해야 하며(SHALL), "질문 받기"와 "다시 쓰기만" 두 방식을 고르게 해야 한다(SHALL). 첫 실행 전 네이티브 확인 창에 예상 비용 상한과 "브리프가 Claude로 전송됩니다"를 보여야 한다(SHALL). CLI가 없으면 비활성화하고 이유를 보여야 한다(SHALL).

#### Scenario: 질문 받기 시작
- **WHEN** 사용자가 목표에 "로그인 가끔 실패 고치기"만 적고 "질문 받기"를 누른 뒤 확인한다
- **THEN** 질문 카드 3~8개(팀 설정, 기본 5)가 나타나고 각 카드에 선택지와 미리 선택된 추천이 있다

### Requirement: 선택형 답
각 질문은 선택지 2~4개와 추천 하나를 가져야 하며(SHALL), 추천이 기본 선택되어 있어야 한다(SHALL). 사용자는 선택지를 고르거나, 짧은 직접 입력(200자 이하)을 하거나, 건너뛸 수 있어야 한다(SHALL). 여러 개를 고를 수 있는 질문은 그렇게 표시해야 한다(SHALL). 키보드만으로 고르고 제출할 수 있어야 한다(SHALL).

#### Scenario: 추천 그대로 다음 라운드
- **WHEN** 사용자가 아무것도 바꾸지 않고 "답하고 계속"을 누른다
- **THEN** 추천 답들로 다음 라운드 질문과 갱신된 브리프 제안이 온다

#### Scenario: 라운드 상한
- **WHEN** 3라운드를 마쳤거나 Claude가 더 물을 것이 없다고 답한다
- **THEN** 질문 대신 "다듬기 완료"와 최종 브리프 제안만 보인다

### Requirement: 다시 쓴 브리프 적용
매 응답의 브리프 제안(목표·범위 밖·제약·완료 기준)은 현재 값과 필드별 전/후로 보여야 하며(SHALL), 필드별·전체 적용과 적용 직전 상태로 되돌리기를 제공해야 한다(SHALL). 적용 전에는 폼 값을 바꾸지 않아야 한다(MUST NOT).

#### Scenario: 완료 기준만 적용
- **WHEN** 사용자가 완료 기준 제안만 "적용"한다
- **THEN** 완료 기준만 바뀌고 나머지 필드는 그대로이며 "되돌리기"로 이전 값이 돌아온다

### Requirement: 안전한 실행
다듬기 실행은 도구를 하나도 쓰지 않아야 하고(MUST NOT), 사용자·프로젝트 설정과 MCP를 불러오지 않아야 하며(MUST NOT), 세션 기록을 남기지 않아야 한다(MUST NOT). 한 번 실행의 비용은 상한을 넘지 않아야 한다(SHALL). 응답은 스키마로 검증하고 개수·길이 상한을 넘거나 형식이 틀리면 버리고 오류를 보여야 한다(SHALL). 응답 내용은 텍스트로만 그려야 한다(SHALL). 브리프·질문·답·제안은 DB와 로그에 저장하지 않아야 한다(MUST NOT).

#### Scenario: 형식이 틀린 응답
- **WHEN** CLI 결과가 스키마에 맞지 않는다
- **THEN** "Claude 응답을 읽지 못했습니다. 다시 시도하세요"가 보이고 폼 값은 바뀌지 않는다

#### Scenario: 비용 표시
- **WHEN** 한 라운드가 끝난다
- **THEN** 이번 라운드 비용과 누적 비용(API 환산 추정)이 보인다

### Requirement: 개선 제안에서 작업 시작
사용 개선 분석의 각 로컬 점검 결과와 Claude 권고의 각 항목에는 "작업으로 만들기"가 있어야 한다(SHALL). 누르면 새 작업 폼이 그 제안으로 채운 초안 브리프(목표=할 일, 제약=근거 숫자와 "설정 변경은 먼저 diff를 보여 주고 확인 후 적용", 완료 기준=제안의 효과를 확인할 방법)와 알맞은 작업 유형으로 열리고(SHALL), "어디서 온 작업인지" 배지를 보여야 한다(SHALL). 폼은 곧바로 "질문 받기"를 제안해 사용자가 선택형 질문으로 핑퐁하며 다듬은 뒤 시작할 수 있어야 한다(SHALL). 작업 폴더는 사용자가 고르며, 제안이 전역 설정에 관한 것이면 기본값으로 홈의 `.claude` 상위(홈 폴더)를 미리 고른다(SHALL). 초안을 만드는 것만으로는 아무것도 실행하거나 전송하지 않아야 한다(MUST NOT).

#### Scenario: 서브에이전트 모델 제안을 작업으로
- **WHEN** 사용자가 "서브에이전트가 대부분 Opus를 상속" 점검 결과의 "작업으로 만들기"를 누른다
- **THEN** 새 작업 폼이 목표 "리뷰·QA 에이전트 정의에 model 지정"과 근거·완료 기준이 채워진 채 열리고, "질문 받기로 다듬기" 안내가 보이며, 시작 전에는 아무것도 실행되지 않는다

#### Scenario: Claude 권고 항목을 작업으로
- **WHEN** Claude 권고의 '비용 줄이기' 섹션 두 번째 항목에서 "작업으로 만들기"를 누른다
- **THEN** 그 항목의 문장이 목표·근거로 들어간 초안이 열린다
