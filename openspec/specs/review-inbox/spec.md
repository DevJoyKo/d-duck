## Requirements

### Requirement: 사이드바 리뷰 탭과 배지
사이드바 "작업 공간" 묶음에 "리뷰" 항목이 "작업" 바로 다음에 있어야 한다(SHALL). 항목 배지는 리뷰 전 작업 수(아래 정의)를 보여야 하며(SHALL), 0이거나 작업 목록을 읽지 못했으면 배지를 그리지 않는다(SHALL). 배지의 접근 이름은 "리뷰 전 N개"여야 하고, 작업 탭 배지의 접근 이름은 "확인 필요 N개"여야 한다(SHALL). 페이지 id는 `review`이며 기억된 페이지·`?page=` 링크에서 정적 허용 목록으로만 받아야 한다(SHALL).

#### Scenario: 모두 리뷰함
- **WHEN** 리뷰 전 작업이 0개다
- **THEN** "리뷰" 항목에 배지가 없다

### Requirement: 리뷰 전 작업의 정의
"리뷰 전 작업"은 D.Duck이 보고서를 붙여 시작한 작업 기록과 보고서가 붙은 루틴 실행 중 리뷰했어요 표시가 없고, 실행 중이 아니며, 리뷰 기준 시각 이후에 시작한 것이어야 한다(SHALL). 루틴 실행의 시작 시각은 실제로 시작한 시각이고, 없으면 예정 시각이다(SHALL). "실행 중"은 작업 목록 상태가 끝남(완료·실패·중지·알 수 없음)이 아닌 것이고, 목록에 없는 작업은 끝난 것으로 본다(SHALL, 보고서 화면과 같은 규칙). 리뷰 기준 시각은 처음 한 번 정해지고 바뀌지 않아야 한다(SHALL). 정리 끝인 기록은 리뷰 전이 아니다(SHALL). 보고서 파일이 없거나 형식 오류여도 끝난 작업이면 센다(SHALL). 같은 작업 id에 작업 기록과 루틴 실행이 함께 있으면 작업 기록 하나로만 센다(SHALL).

#### Scenario: 배지 개수
- **WHEN** 기준 시각 이후 보고서가 붙은 끝난 작업 3개 중 1개가 리뷰했어요 표시되어 있고, 보고서가 붙은 작업 1개가 아직 실행 중이다
- **THEN** 사이드바 "리뷰" 배지는 2이고 접근 이름은 "리뷰 전 2개"다

#### Scenario: 처음 켰을 때 쏟아지지 않음
- **WHEN** 이 기능이 생기기 전에 보고서가 붙은 끝난 작업이 30개 있다
- **THEN** 업데이트 후 첫 실행에서 배지가 없고 리뷰 전 필터는 "모두 리뷰했어요"이며, 그 30개는 전체 필터에서 보인다

#### Scenario: 루틴 실행 보고서
- **WHEN** 기준 시각 이후 루틴이 실행되어 보고서를 남기고 끝났다
- **THEN** 리뷰 탭 리뷰 전 필터에 그 카드가 보이고 사이드바 배지가 1 늘며, 작업 보드 리뷰 대기 칸 수도 같이 1 는다

#### Scenario: 업데이트 직후 루틴 보고서
- **WHEN** 리뷰 기준 시각 이후 리뷰하지 않은 루틴 보고서 3개가 이미 있는 상태에서 이 업데이트를 연다
- **THEN** 배지가 3이고 세 카드가 리뷰 전에 보인다(리뷰했다고 대신 표시하지 않는다)

#### Scenario: 루틴 보관 정리
- **WHEN** 한 루틴의 보고서가 21개째 생긴다
- **THEN** 가장 오래된 보고서 카드가 리뷰 여부와 상관없이 리뷰 탭에서 빠진다(보고서 보관 규칙)

#### Scenario: 기록 삭제와 루틴 보고서
- **WHEN** 사용자가 작업 기록을 모두 삭제한다
- **THEN** 루틴 실행 보고서 카드는 남고, 그 루틴을 지우면 함께 사라진다

#### Scenario: 기준 시각 전 루틴 보고서
- **WHEN** 기준 시각 전에 끝난 루틴 실행에 보고서가 있다
- **THEN** 배지에는 세지 않고 전체 필터에서만 보인다

### Requirement: 역할별로 묶인 결과 카드
리뷰 탭은 보고서가 붙은 D.Duck 작업 기록과 루틴 실행을 역할(작업 유형)별 묶음으로 보여야 한다(SHALL). QA·리뷰 작업도 자기 역할 묶음에 나온다(SHALL). 루틴 실행은 유형 없음("기본") 묶음에 들고, 폴더·시각 줄 앞에 "루틴"을 붙여야 한다(SHALL). 묶음 머리는 그 역할의 오리(역할 고정 색, 역할 칩)와 이름, 묶음 안 카드 수여야 한다(SHALL). 묶음 순서는 팀 설정의 유형 순서, 그 뒤 삭제된 유형, 마지막에 유형 없음("기본")이어야 하고(SHALL), 카드는 묶음 안에서 최신 순이어야 한다(SHALL). 보고서가 없는 루틴 실행과 D.Duck 밖에서 시작한 세션은 보이지 않는다(SHALL NOT 표시). 보고서 없이 시작한 D.Duck 작업(원격 조작 포함)은 아래 "보고서 없는 작업" 요구사항대로 전체 필터에만 보인다. 앱이 기록한 연결이 없는 보고서 폴더는 내용이나 시각으로 주인을 짐작해 보여 주지 않는다(MUST NOT).

#### Scenario: 두 역할
- **WHEN** 개발 작업 2개와 QA 작업 1개에 보고서가 있다
- **THEN** 개발 묶음(카드 2개, 최신 먼저)과 QA 묶음(카드 1개)이 팀 설정 순서대로 보이고, 각 묶음 머리 오리는 보고서 화면과 같은 역할 색이다

#### Scenario: 루틴 카드
- **WHEN** 이름이 "아침 공고 확인"인 루틴 실행에 보고서가 있다
- **THEN** "기본" 묶음에 목표 "아침 공고 확인" 카드가 보이고 폴더·시각 줄이 "루틴 · <폴더> · <시각>"이며, 누르면 맡긴 내용에 "루틴" 칩이 있는 보고서 화면이 열린다

### Requirement: 카드 내용
카드마다 한 줄씩 다음을 보여야 한다(SHALL): ① 맡긴 내용(브리프 목표, 없으면 작업 이름, 없으면 지시 첫 줄, 120자까지; 셋 다 없으면 시작 시각을 앞에 둔 "목표를 남기지 않은 작업이에요") ② 판정 줄(보고서 화면 머리와 같은 계산·문구)과 같은 줄에 폴더 이름·시작 시각 ③ 완료 기준 "충족 N · 일부 충족 M · 못 했어요 K"(0인 부분은 빼고, 기준이 없으면 생략) ④ 먼저 확인할 것의 첫 1개(라벨과 글; 없거나, 하나뿐이고 판정 줄이 이미 그 라벨을 말하면 생략). 실행 중이면 판정 줄 대신 상태 줄을 보여야 하고(SHALL, 답을 기다리는 중이면 "답을 기다려요", 그 밖에는 "일하는 중이에요"), 끝났는데 보고서가 준비되지 않았으면 "보고서가 아직 없어요" 또는 형식 오류 문구를 보여야 한다(SHALL). 모든 문구는 해요체이고 "리뷰"를 쓰며 "검토"를 쓰지 않는다(MUST NOT).

#### Scenario: 보고서가 있는 개발 작업
- **WHEN** 끝난 개발 작업의 보고서에 기준 3개(충족 2, 일부 충족 1)와 묻지 않고 정한 결정 1개가 있다
- **THEN** 카드에 목표 한 줄, 주의 색 "일부 충족 1 · 묻지 않고 정함 1 → 확인이 필요해요", "충족 2 · 일부 충족 1", 첫 확인 칩 "일부 충족 …"이 보인다

#### Scenario: 못 한 기준
- **WHEN** 기준 3개 중 충족 2, 못 함 1이고 다른 확인할 것이 없다
- **THEN** 카드에 빨간 "못 했어요 1 → 확인이 필요해요"와 "충족 2 · 못 했어요 1"이 보이고, 같은 말을 되풀이하는 확인 칩은 없다

#### Scenario: 보고서 없이 끝남
- **WHEN** 보고서가 붙어 시작했지만 report.json이 없이 끝난 작업이다
- **THEN** 카드는 "보고서가 아직 없어요"와 맡긴 내용을 보이고, 리뷰 전 필터와 배지에 포함된다

#### Scenario: 실행 중
- **WHEN** 보고서가 붙은 작업이 아직 일하는 중이다
- **THEN** 리뷰 전 필터와 배지에 들어가지 않고, 전체 필터에서 "일하는 중이에요"와 함께 보이며 리뷰했어요 버튼이 없다

#### Scenario: 답을 기다리는 작업
- **WHEN** 보고서가 붙은 작업이 사용자 입력을 기다리고 있다
- **THEN** 리뷰 전 필터와 배지에 들어가지 않고, 전체 필터에서 "답을 기다려요"와 함께 보이며 리뷰했어요 버튼이 없다

#### Scenario: 실행 여부를 아직 모름
- **WHEN** 앱을 켠 뒤 작업 목록을 아직 한 번도 제대로 읽지 못했다(또는 마지막 읽기가 실패했다)
- **THEN** 리뷰했어요 표시가 없는 카드는 "실행 여부 확인 중"으로 보이고 리뷰했어요 버튼이 없으며, 앱은 표시 요청을 거절하고 배지를 숨긴다

#### Scenario: QA 작업이 아직 실행 중
- **WHEN** 개발 작업은 끝났고 그 결과를 보는 QA 작업은 아직 실행 중이다
- **THEN** 개발 카드는 리뷰 전에 보이고, QA 카드는 QA 묶음에서 전체 필터에만 "일하는 중이에요"로 보인다

### Requirement: 카드 색과 묶음 머리
판정 줄은 확인할 것이 있으면 주의 색, 못 한 기준이 있을 때만 위험(빨강) 색, 형식 오류는 주의 색이어야 한다(SHALL). 묶음마다 한 장의 시트, 머리(오리 28px·역할 칩·전체 개수)는 스크롤해도 위에 붙어 있어야 한다(SHALL). 묶음 머리 개수는 다른 쪽의 카드까지 센 그 역할의 전체 수여야 한다(SHALL).

#### Scenario: 형식 오류 색
- **WHEN** 끝난 작업의 보고서 형식이 맞지 않는다
- **THEN** 카드 판정 줄이 빨강이 아닌 주의 색으로 "보고서 형식이 맞지 않아 보여 드릴 수 없어요"를 보인다

### Requirement: 쪽 나누기와 카드 미리보기
리뷰 탭은 아티팩트 탭과 같은 쪽 넘김(10개씩, 이전·쪽 번호·다음)을 써야 하고(SHALL), 역할 묶음은 지금 쪽 안에서 나눈다(SHALL). 목록이 세는 카드(최대 500개)는 모든 쪽에서 열려야 하며 마지막 쪽까지 오류가 나지 않아야 한다(SHALL). 필터나 범위를 바꾸면 1쪽으로 돌아가야 한다(SHALL). 카드는 판정 줄 아래에 완료 기준을 3줄까지(표시·기준·근거 한 줄) 보이고, 더 있으면 "+N개 더"를 보여야 한다(SHALL). 근거는 한 줄 120자까지만 목록에 실린다(SHALL).

#### Scenario: 두 쪽
- **WHEN** 리뷰 전 작업이 20개다
- **THEN** 1쪽에 카드 10개와 쪽 넘김이 보이고, "2쪽"을 누르면 다음 10개가 보이며, "전체"로 바꾸면 1쪽부터 다시 보인다

#### Scenario: 22쪽 넘어
- **WHEN** 보고서가 붙은 기록이 300개다
- **THEN** 쪽 넘김이 30쪽까지 있고 30쪽에 마지막 10개가 오류 없이 보인다

#### Scenario: 기준 미리보기
- **WHEN** 끝난 작업의 보고서에 완료 기준이 4개 있다
- **THEN** 카드에 처음 3개 기준이 표시와 근거 한 줄과 함께 보이고 "+1개 더"가 붙으며, 카드를 누르면 전체 보고서가 열린다

### Requirement: 리뷰했어요 모양과 차례 흐름
표시하면 5초 동안 "리뷰했어요 · 되돌리기"를 보여야 한다(SHALL). 리뷰했어요 표시된 카드는 흐리게, "✓ 리뷰 끝" 칩과 "되돌리기"로 보여야 한다(SHALL). 보고서 화면 아래에는 "리뷰했어요 · 다음"(표시하고 다음 리뷰 전 카드를 연다)과 "닫기"가 있어야 한다(SHALL). 사이드바 리뷰 배지는 노랑이 아닌 중립 색이어야 한다(SHALL).

#### Scenario: 되돌리기 알림
- **WHEN** 사용자가 리뷰 전 카드의 "리뷰했어요"를 누른다
- **THEN** 5초 동안 "리뷰했어요 · 되돌리기"가 보이고, 되돌리기를 누르면 카드가 다시 리뷰 전에 나온다

### Requirement: 필터와 프로젝트
리뷰 탭에는 [리뷰 전 | 전체] 필터가 있어야 하고 기본은 리뷰 전이어야 한다(SHALL). 리뷰 탭은 모든 프로젝트(전역)로 시작해야 하며(SHALL), 자기 프로젝트 선택(D-127, ScopeBar·⌘P)으로 좁힐 수 있어야 한다(SHALL). 프로젝트를 고르면 그 프로젝트 폴더와 그 아래 폴더(worktree 포함)에서 시작한 작업만 보여야 하고(SHALL), 리뷰 전 필터에서 다른 프로젝트의 리뷰 전 작업이 있으면 "다른 프로젝트에 N개 더" 한 줄을 보여 배지 수와 맞춰야 한다(SHALL). 배지는 프로젝트와 상관없이 전체 개수다(SHALL). 고른 프로젝트를 찾을 수 없으면 전역으로 넘어가지 않고 오류 한 줄을 보여야 한다(SHALL). 리뷰 탭의 프로젝트는 스킬·에이전트 목록의 프로젝트 폴더에 더하지 않는다(MUST NOT).

#### Scenario: 처음 열기
- **WHEN** 사용자가 리뷰 탭을 처음 연다
- **THEN** ScopeBar는 "모든 프로젝트" 쪽이 골라져 있고 모든 프로젝트의 카드가 보인다

#### Scenario: 프로젝트 좁히기
- **WHEN** 리뷰 전 작업이 프로젝트 A에 2개, B에 1개 있고 사용자가 A를 고른다
- **THEN** A의 카드 2개와 "다른 프로젝트에 1개 더"가 보이고, 다른 탭의 프로젝트 선택과 사이드바 배지(3)는 그대로다

#### Scenario: 전체 필터
- **WHEN** 사용자가 "전체"를 고른다
- **THEN** 리뷰했어요 표시된 카드도 "리뷰했어요" 표시와 함께 보이고, 실행 중인 카드와 기준 시각 전 작업도 보인다

### Requirement: 보고서 열기와 리뷰했어요
카드를 누르거나 Enter를 누르면 기존 보고서 화면(같은 대화상자, 같은 내용)이 열려야 한다(SHALL). 끝난 작업 카드에는 "리뷰했어요" 버튼이 있어야 하며(SHALL, 노랑은 차례상 첫 카드 하나에만, 나머지는 일반 버튼), 누르면 그 작업에 리뷰했어요 표시가 저장되고 리뷰 전 필터에서 빠지며 배지가 줄어야 한다(SHALL). 앱은 실행 중인 작업과 보고서가 붙지 않은 작업의 표시 요청을 거절해야 한다(SHALL). 리뷰 탭에서는 보고서가 있는 작업이면 유형과 상관없이 표시할 수 있다(SHALL). 루틴 실행도 같은 규칙으로 표시·되돌리기가 되어야 하고, 그 표시는 그 루틴 실행에 저장된다(SHALL). 표시는 작업 탭의 같은 상태와 하나의 값이어야 한다(SHALL).

#### Scenario: 차례로 리뷰
- **WHEN** 리뷰 전 필터에서 사용자가 첫 카드의 "리뷰했어요"를 누른다
- **THEN** 그 카드가 목록에서 빠지고 다음 카드에 포커스가 가며 배지가 1 줄고, 작업 탭의 같은 작업에도 "리뷰했어요"가 보인다

#### Scenario: 보고서에서 차례로
- **WHEN** 사용자가 첫 카드 보고서에서 "리뷰했어요 · 다음"을 누른다
- **THEN** 그 작업이 표시되고 다음 리뷰 전 카드의 보고서가 열린다

#### Scenario: 실수로 표시
- **WHEN** 사용자가 전체 필터에서 리뷰했어요 카드의 "되돌리기"를 누른다
- **THEN** 표시가 지워지고 그 카드가 다시 리뷰 전에 포함되며 배지가 1 는다

#### Scenario: 루틴 실행 리뷰
- **WHEN** 사용자가 루틴 실행 카드의 "리뷰했어요"를 누른다
- **THEN** 그 카드가 리뷰 전에서 빠지고 배지와 리뷰 대기 칸 수가 함께 1 준다

### Requirement: 문구 정리
앱 안의 "리뷰함" 버튼·표시·설명은 "리뷰했어요"로 바뀌어야 한다(SHALL). 작업 보드의 "리뷰 필요" 칸과 그 칸을 가리키는 안내는 "확인 필요"로 바뀌어야 한다(SHALL, D-123 일부 대체).

#### Scenario: 보드 칸 이름
- **WHEN** 사용자가 작업 탭 보드를 본다
- **THEN** 답을 기다리거나 실패한 작업 칸의 이름이 "확인 필요"이고, 화면 어디에도 "리뷰함"이 없다

### Requirement: 빈 화면
빈 화면은 쉬는 오리와 한 줄이어야 한다(SHALL). 보고서가 붙은 작업이 하나도 없으면 "아직 보고서가 있는 작업이 없어요"(SHALL). 작업 보고서 설정이 꺼져 있고 기록도 없으면 "보고서를 켜면 오리들이 결과를 모아 와요"와 설정 열기 버튼만 보이고 범위·필터는 숨겨야 한다(SHALL). 꺼지기 전에 남은 보고서가 있으면 카드 위에 "작업 보고서가 꺼져 있어요 · 설정 열기" 한 줄을 띄운다(SHALL). 리뷰 전이 0개인데 기록은 있으면 "모두 리뷰했어요", 실행 중인 작업이 있으면 "모두 리뷰했어요 · 일하는 중 N개"(SHALL).

#### Scenario: 설정 꺼짐
- **WHEN** 작업 보고서 설정이 꺼져 있고 보고서가 붙은 기록이 없다
- **THEN** "보고서를 켜면 오리들이 결과를 모아 와요"와 "설정 열기" 버튼만 보이고(범위·필터 없음), 누르면 설정 탭이 열린다

### Requirement: 비용과 프라이버시
리뷰 탭은 새 Claude 호출을 하지 않아야 한다(MUST NOT). 목록 응답은 카드 요약(맡긴 내용 120자, 완료 기준 줄, 판정에 필요한 항목, 기준별 근거 120자)만 담고 전체 지시·브리프·작업 단계·결정 이유·120자를 넘는 근거를 담지 않아야 한다(MUST NOT); 전체 내용은 카드를 열 때 기존 보고서 화면 경로로만 읽는다(SHALL). 보고서 내용, 보고서 경로·id, transcript 원문을 DB·로그·오류 문구에 남기지 않아야 하며(MUST NOT), 보고서는 기존 안전 읽기(링크 거부, 1MB, 형식 검증)로만 읽는다(SHALL). 웹뷰에는 보고서 id와 경로를 보내지 않는다(MUST NOT). 탭은 주기적으로 모든 보고서를 다시 읽지 않는다(SHALL).

#### Scenario: 목록에 전체 지시 없음
- **WHEN** 작업 지시가 120자를 넘고 고유한 문자열을 담고 있다
- **THEN** 목록 응답에는 그 문자열의 앞 120자 이내만 있고 뒷부분은 없다

#### Scenario: 오류에도 경로 없음
- **WHEN** 보고서 폴더가 링크로 바뀌어 읽기가 거부된다
- **THEN** 카드는 "보고서 파일이 안전하지 않아 읽지 않았어요"를 보이고, 응답·로그 어디에도 경로나 id가 없다

### Requirement: 보고서 없는 작업
전체 필터는 보고서 없이 시작해 끝난 D.Duck 작업 기록도 같은 목록·쪽 넘김 안에서 최신 순으로 보여야 한다(SHALL, D-196). 실행 중이거나, 작업 목록을 아직 한 번도 제대로 읽지 못했으면 넣지 않는다(SHALL). 이 카드는 작업 이름·역할 묶음·폴더·시각과 끝난 상태 한 줄("끝냈어요"·"실패했어요"·"멈췄어요"·"끝났어요"), "보고서 없음" 칩을 보여야 한다(SHALL). "리뷰했어요"·"보고서 열기"는 없고(MUST NOT), "작업 보기" 하나만 있어야 한다(SHALL). "작업 보기"는 작업 목록에 있으면 작업 보드의 그 작업 서랍을, 없으면 작업 탭 지난 작업의 그 기록을 펼쳐 열어야 한다(SHALL). 이 작업은 리뷰 전·사이드바 배지·작업 보드 리뷰 대기 칸에 세지 않는다(MUST NOT). 같은 작업 id에 루틴 보고서가 있으면 루틴 카드 하나만 보인다(SHALL). 목록에는 지시 원문을 싣지 않는다(MUST NOT).

#### Scenario: 보고서 없는 끝난 작업
- **WHEN** 작업 보드에서 보고서 없이 시작한 조사 작업이 끝났다
- **THEN** 리뷰 전 필터와 배지에는 없고, 전체 필터의 조사 묶음에 "보고서 없음" 칩과 "끝냈어요"가 있는 카드로 보이며 "리뷰했어요" 버튼이 없다

#### Scenario: 작업 보기
- **WHEN** 작업 목록에서 이미 사라진 그 카드의 "작업 보기"를 누른다
- **THEN** 작업 탭으로 가서 지난 작업의 그 기록이 펼쳐진 채로 보이고, 보고서 화면은 열리지 않는다

#### Scenario: 밖에서 시작한 세션
- **WHEN** 터미널에서 직접 시작한 세션이 작업 목록에 있다
- **THEN** 리뷰 탭 어느 필터에도 보이지 않는다

### Requirement: 카드 삭제
리뷰 탭의 끝난 카드(보고서 있는 작업, 보고서 없는 작업, 루틴 실행)마다 "지우기"가 있어야 한다(SHALL, 앱의 다른 지우기와 같은 이름, 평소엔 흐린 글자이고 가리킬 때만 위험 색). 실행 중·답을 기다리는 카드와 실행 여부를 아직 모르는 카드, 시작 중인 루틴 실행에는 없어야 한다(MUST NOT). 삭제는 앱의 네이티브 확인 창을 거쳐야 하며(SHALL), 창은 지워지는 것(작업 기록과 보고서의 근거·첨부, 되돌릴 수 없음)과 남는 것(Claude 세션 기록, git worktree·브랜치)을 말해야 한다(SHALL). worktree로 시작한 작업이면 먼저 정리하라는 줄을 더해야 한다(SHALL). CLI 목록에 아직 있는 세션은 지운 뒤 보드에 다시 나오지 않아야 한다(MUST NOT). 작업 기록은 지난 작업 삭제와 같이 기록·지시·보고서 폴더를 지운다(SHALL). 루틴 실행은 보고서 폴더와 보고서 연결·리뷰 상태만 지우고 실행 기록은 남긴다(SHALL). 앱은 실행 중인 작업, 이어서 하기가 예약된 작업, 확인 창이 열린 동안 다시 시작된 작업의 삭제를 거절해야 한다(SHALL). 지운 뒤 배지·보드 리뷰 대기와 정리 칸·리뷰 탭 수가 바로 바뀌고 포커스는 다음 카드로 가야 한다(SHALL). 보고서 폴더는 보고서 루트 안의 올바른 id 폴더만 지워야 한다(SHALL).

#### Scenario: 보고서 있는 작업 삭제
- **WHEN** 리뷰 전 카드의 "지우기"를 누르고 확인 창에서 "지우기"를 고른다
- **THEN** 카드가 사라지고 배지와 리뷰 대기 칸이 1 줄며, 지난 작업에서도 사라지고 보고서 폴더가 없어진다

#### Scenario: 취소
- **WHEN** 확인 창에서 "취소"를 고른다
- **THEN** 아무것도 바뀌지 않는다

#### Scenario: 루틴 실행 삭제
- **WHEN** 루틴 실행 카드를 지운다
- **THEN** 리뷰 탭과 배지에서 빠지고 보고서 폴더가 없어지며, 루틴 탭 실행 기록에는 그 실행이 남는다

#### Scenario: 실행 중
- **WHEN** 작업이 아직 일하는 중이다
- **THEN** 카드에 "지우기"가 없고, 명령을 직접 보내도 거절된다

#### Scenario: worktree가 남은 작업
- **WHEN** worktree로 시작해 정리 끝을 누르지 않은 작업을 지우려 한다
- **THEN** 확인 창에 "먼저 작업 탭 정리에서 worktree를 지워 주세요" 줄이 있다

#### Scenario: 보고서 없는 작업 삭제
- **WHEN** 전체 필터의 "보고서 없음" 카드를 지운다
- **THEN** 카드가 사라지고 지난 작업에서도 사라지며 배지는 그대로다

#### Scenario: 이어서 하기가 예약된 작업
- **WHEN** 사용 한도 뒤 이어서 하기가 예약된 작업을 지우려 한다
- **THEN** 앱이 거절하고 오류 줄에 이유가 보인다

#### Scenario: 확인 창이 열린 동안 다시 시작
- **WHEN** 확인 창이 열린 동안 그 작업이 다시 일하기 시작하고 사용자가 "지우기"를 고른다
- **THEN** 앱이 거절하고 아무것도 지우지 않는다

#### Scenario: 목록에 남은 세션
- **WHEN** CLI 목록에 아직 있는 끝난 작업을 지운다
- **THEN** 작업 보드 어느 칸에도 다시 나오지 않는다

#### Scenario: 포커스
- **WHEN** 카드를 지운다
- **THEN** 포커스가 다음 카드의 열기 버튼으로 간다(없으면 앞 카드)

#### Scenario: 보고서 폴더 경로
- **WHEN** 보고서 루트가 링크이거나 기록의 보고서 id가 올바르지 않다
- **THEN** 루트 밖이나 다른 폴더는 지우지 않는다
