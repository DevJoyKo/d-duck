# team-presets-editable Specification

## Purpose
작업에 붙는 팀 규칙과 작업 유형별 역할·권한·effort를 앱을 다시 빌드하지 않고 에이전트 탭에서 조절하게 한다.

## Requirements

### Requirement: 팀 규칙 편집

에이전트 탭의 팀 설정에서 팀 규칙을 보고 고치고 추가·삭제·순서 변경할 수 있어야 한다(SHALL). 안전 규칙은 잠금으로 표시되고 삭제할 수 없어야 한다(MUST NOT). 저장한 규칙은 이후 D.Duck이 시작하는 모든 작업과 루틴 실행에 적용되어야 한다(SHALL).

#### Scenario: 규칙 추가
- **WHEN** 사용자가 "커밋 메시지는 한국어로 쓴다" 규칙을 추가하고 저장한다
- **THEN** 다음에 시작하는 작업의 시스템 지시에 그 규칙이 포함된다

#### Scenario: 안전 규칙 삭제 시도
- **WHEN** 사용자가 "기본 브랜치에 직접 커밋하지 않는다" 규칙을 지우려 한다
- **THEN** 삭제 버튼이 비활성이고 "안전 규칙은 지울 수 없습니다"가 보인다

### Requirement: 작업 유형 편집

사용자는 각 작업 유형의 이름, 역할(번들 또는 내 에이전트), 역할 프롬프트와 도구, 기본 권한과 고를 수 있는 권한, 기본 effort, 리뷰 용량 대상 여부, 엄격 여부를 고치고, 유형을 추가하거나 숨길 수 있어야 한다(SHALL). Composer의 유형 선택지는 저장된 설정을 따라야 한다(SHALL).

#### Scenario: 학습 유형 effort 바꾸기
- **WHEN** 사용자가 "학습" 유형의 기본 effort를 높음으로 바꾸고 저장한다
- **THEN** Composer에서 학습을 고르면 effort가 높음으로 채워지고 시작한 작업에 `--effort high`가 붙는다

### Requirement: 안전 불변식

어떤 설정으로도 위험 권한 모드를 유형의 허용 권한에 넣을 수 없어야 하며(MUST NOT), 민감 영역·원격 조작 제한은 설정과 관계없이 적용되어야 한다(MUST). 엄격 유형을 해제하거나 검토·보안 유형에 쓰기·명령 도구를 추가하면 저장 전 확인 창이 떠야 한다(SHALL).

#### Scenario: 위험 권한 추가 시도
- **WHEN** 저장된 설정에 어떤 유형의 허용 권한으로 위험 모드가 들어 있다(직접 편집 등)
- **THEN** 앱은 그 설정을 거부하고 기본값으로 작업을 시작하며 설정 화면에 오류를 보인다

### Requirement: 기본값 복원

항목별·전체 "기본값으로 되돌리기"가 있어야 하고(SHALL), 앱이 업데이트되어 기본값이 바뀌면 사용자가 고치지 않은 항목은 새 기본값을 따라야 한다(SHALL).

#### Scenario: 일부만 고친 경우
- **WHEN** 사용자가 "개발" 유형만 고쳤고 앱 업데이트로 "QA" 기본 프롬프트가 바뀌었다
- **THEN** 개발은 사용자 값, QA는 새 기본값이 쓰인다

### Requirement: 에이전트 켜기·끄기·숨기기·삭제

에이전트 탭의 톱니바퀴로 여는 설정에서 각 에이전트를 끄고 켤 수 있어야 한다(SHALL). 끄기는 Claude Code 권한 규칙 `Agent(이름)`을 해당 범위 settings의 deny에 넣는 방식이어야 하며(SHALL) 정의 파일을 바꾸지 않는다. 숨기기는 D.Duck 화면에서만 적용되어야 한다(SHALL). 삭제는 사용자·프로젝트 에이전트에만 가능하고, 확인 후 정의 파일을 휴지통으로 옮겨야 한다(SHALL). 내장·플러그인 에이전트는 삭제할 수 없어야 한다(MUST NOT).

#### Scenario: 끄기
- **WHEN** 사용자가 사용자 에이전트 "code-reviewer"를 끈다
- **THEN** 전역 settings의 permissions.deny에 `Agent(code-reviewer)`가 추가되고, 카드에 "꺼짐"이 보이며 Composer 역할 목록에서 빠진다. 다시 켜면 그 규칙만 빠진다

#### Scenario: 숨기기
- **WHEN** 사용자가 내장 에이전트 "statusline-setup"을 숨긴다
- **THEN** 카드 목록에서 사라지고 settings 파일은 바뀌지 않으며, "숨긴 에이전트 보기"에서 다시 보이게 할 수 있다

#### Scenario: 삭제
- **WHEN** 사용자가 프로젝트 에이전트 "old-helper"를 삭제하고 확인한다
- **THEN** 정의 파일이 휴지통으로 옮겨지고 목록에서 사라진다. 플러그인 에이전트에는 삭제 버튼이 없다
