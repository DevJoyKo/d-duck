## Requirements

### Requirement: 역할을 가진 오리 이야기로 된 투어
투어는 이야기 카드 5장과 마지막 행동 카드 1장으로 구성되어야 한다(SHALL). 순서는 ① "세션 하나에 다 시키고 있나요?" → ② "D.Duck에선 오리마다 역할이 있어요" → ③ "틀에 맞춰 맡기고, 고르기만 하면 다듬어져요" → ④ "누가 무엇을 하고 있는지 보여요" → ⑤ "오리마다 한 일을 보고서로 확인해요" → 행동 "내 일로 첫 작업 맡겨 보기"여야 한다(SHALL). 카드마다 핵심 문장 1줄과 보조 1줄만 두고(SHALL), 탭 이름을 하나씩 소개하는 카드나 웰컴·마무리 카드를 두지 않아야 한다(MUST NOT). 문구는 한 줄 해요체여야 한다(SHALL).

#### Scenario: 처음 실행
- **WHEN** 새로 설치한 사용자가 앱을 연다
- **THEN** 첫 카드에 "세션 하나에 다 시키고 있나요?"와 진행 "1/5"가 보이고, 넘기면 역할 → 맡기기·다듬기 → 진행 보드 → 보고서 → 행동 카드 순서로 이어진다

#### Scenario: 넘기기와 닫기
- **WHEN** 사용자가 카드(버튼·점·링크·선택한 글자 제외)를 누르거나 →·Space를 누른다
- **THEN** 다음 카드로 넘어가고, ←는 이전 카드, Esc는 덱을 닫아 '건너뜀'으로 저장한다. 건너뛰기는 행동 카드 전까지 모든 카드에 있다

### Requirement: 진행 표시가 한 가지 기준을 쓴다
진행 글자는 이야기 카드에서 "n/5", 행동 카드에서 "직접 해 보기"여야 한다(SHALL). 진행 점은 이야기 카드마다 둥근 점 1개(5개)와, 그와 모양이 다른 행동 카드 표시 1개여야 하며(SHALL), 점의 접근 이름도 같은 기준("n/5: 제목", "직접 해 보기: 제목")을 써야 한다(SHALL).

#### Scenario: 마지막 이야기 카드에서 행동 카드로
- **WHEN** 사용자가 5/5 카드에서 다음으로 넘긴다
- **THEN** 진행 글자는 "직접 해 보기"로 바뀌고, 다섯 점은 모두 현재 표시가 꺼지며 화살표 모양 행동 표시가 현재 표시를 받는다

### Requirement: 오리는 항상 역할 라벨과 함께
투어에 나오는 모든 오리는 역할 라벨 칩과 함께 그려져야 한다(SHALL). 오리 색은 작업 유형 설정과 같은 역할별 고정 색(roleColors)이어야 한다(SHALL). 역할이 없는 오리는 그 사실을 라벨로 밝혀야 한다(SHALL, 카드1 "역할 없음", 행동 카드 "역할 고르기 전"). 오리를 장식(마스코트)으로만 쓰지 않아야 한다(MUST NOT).

#### Scenario: 카드 2 역할 오리
- **WHEN** 사용자가 2번째 카드를 본다
- **THEN** 설계·디자인·개발·리뷰·QA 오리 5마리가 깨어 있는 포즈(일하는 중, 눈 뜸, 56px 이상)로 각자 역할 칩과 일하는 방식 칩 1개를 달고 있다: 설계 "계획부터 · 깊게", 디자인 "화면 · 접근성", 개발 "격리된 곳에서 코드 고치기", 리뷰 "읽기 위주 · 다른 눈", QA "실행해서 확인"
- **AND** 이 칩은 한곳(tour.ts `ROLE_STYLE`)에서 오고, 실제 권한 프리셋(개발=계획만 세우기 등 안전 기본값)은 바꾸지 않으며 카드에 권한·노력 값으로 보이지 않는다

#### Scenario: 마지막 카드 오리
- **WHEN** 사용자가 행동 카드를 본다
- **THEN** 손을 흔드는 오리 한 마리가 "역할 고르기 전" 라벨과 함께 다섯 유형 칩(설계·디자인·개발·리뷰·QA) 옆에 있다

### Requirement: 실제 화면 조각으로 된 데모
카드마다 실제 화면의 표시 전용 조각(OptionLine·questionBox, CriterionLine·Mark, typeChipClass, RoleChip·RoleDuck, statusLine)을 예시 데이터와 원래 크기로 보여야 한다(SHALL, 축소 금지, 오리 36px 이상). 데모는 조작되지 않고(`inert`) 화면 낭독기에서 숨겨지며 카드의 대체 문장을 가져야 한다(SHALL). 데모는 api나 Tauri 브리지를 부르지 않고 원격 이미지·링크를 쓰지 않아야 한다(MUST NOT). 움직임은 카드4 데모만 허용하고 reduced-motion이면 끈다(SHALL). 노랑(duck)은 카드마다 한 곳만 강조에 쓴다(SHALL).

#### Scenario: 카드 3 질문 하나가 요청서를 채운다
- **WHEN** 사용자가 3번째 카드를 본다
- **THEN** 카드2와 같은 다섯 유형 칩 중 개발이 골라져 있고 그 아래 "개발 담당 · 격리된 곳에서 코드 고치기"(카드2와 같은 설명), 추천이 골라진 질문 카드 1장, 그 답이 채운 요청서 줄 "완료 기준: 같은 테스트 20번 연속 통과"가 보인다

#### Scenario: 카드 4 진행 보드
- **WHEN** 사용자가 4번째 카드를 본다
- **THEN** 개발(일하는 중)·리뷰(답을 기다려요)·QA(끝남) 오리 줄 3개가 보이고, 답을 기다리는 줄만 노랑 테두리와 왼쪽 3px 굵은 선(모서리 안쪽)으로 강조된다

#### Scenario: 카드 5 보고서 순서
- **WHEN** 사용자가 5번째 카드를 본다
- **THEN** 개발 오리(done)와 역할 칩, "기준 3개 중 2개 충족" 아래로 맡긴 내용(합의) 줄 → 완료 기준 대조 3줄(✓ 2개, △ 1개) → 주의 칩 "묻지 않고 가정" 1개 → 리뷰 오리 판정 줄 "다른 눈으로 본 판정: 통과 · 1개 확인 필요" 순서로 보인다

### Requirement: 첫 작업으로 이어지되 자동 실행하지 않음
행동 카드의 주 버튼 "첫 작업 맡겨 보기"는 투어를 닫고 새 작업 폼(Composer)을 빈 목표, 예시 목표 칩, 강조된 다듬기 안내와 함께 열어야 한다(SHALL). 유형(역할)은 고르지 않은 상태로 시작한다(SHALL). 아무것도 보내거나 시작하지 않아야 한다(MUST NOT). 구성(확장·MCP·권한·메모리와 규칙) 링크는 버튼과 경쟁하지 않는 ink-3 글자 한 줄이어야 한다(SHALL). Claude CLI가 없으면 설치 명령 복사만 보이고 경로는 보이지 않는다(SHALL).

#### Scenario: 첫 작업 맡겨 보기
- **WHEN** 사용자가 "첫 작업 맡겨 보기"를 누른다
- **THEN** 투어가 '끝냄'으로 닫히고 목표가 비어 있는 새 작업 폼에 예시 칩과 강조된 다듬기 안내가 보이며, 작업 시작·다듬기 실행 요청은 없다

#### Scenario: 구성 링크
- **WHEN** 사용자가 행동 카드의 "권한" 링크를 누른다
- **THEN** 투어가 닫히고 권한 탭이 열린다

### Requirement: 카드 레이아웃
카드는 최대 840px, 왼쪽 문장·오른쪽 데모(768px 미만은 위아래)여야 한다(SHALL). 카드 높이는 가장 긴 카드에 맞춘 한 값(540px, 화면이 낮으면 84vh)으로 고정하고 아래 바는 카드 밑에 붙여(SHALL), 다음 버튼이 카드마다 움직이지 않아야 한다(MUST NOT). 문장과 데모는 세로 가운데에 둔다(SHALL).

#### Scenario: 1440·900px
- **WHEN** 1440px(라이트·다크)와 900px에서 각 카드를 본다
- **THEN** 여섯 장 모두 아래 바와 다음 버튼의 위치가 같고, 문장·데모는 세로 가운데에 있으며 가로 스크롤이 없다

### Requirement: 버전과 기존 사용자
TOUR_VERSION은 2여야 한다(SHALL). 저장 상태의 카드 id는 v1 9개와 v2 6개를 모두 허용하고, 체크리스트 v2 키(refineUsed·reportOpened)는 없으면 false로 채워야 한다(SHALL). 버전 1 투어를 본 사용자에게는 덱을 자동으로 띄우지 않고(MUST NOT) 토스트 "튜토리얼이 새로워졌어요 · 새로워진 안내 보기"를 한 번만 보여야 한다(SHALL). 토스트를 띄우는 순간 버전 2와 v2 카드를 본 것으로 저장한다(SHALL).

#### Scenario: 버전 1 사용자
- **WHEN** 버전 1 투어를 본 사용자가 업데이트 후 앱을 연다
- **THEN** 덱은 열리지 않고 토스트가 한 번 보이며, "새로워진 안내 보기"를 누르면 v2 전체 덱이 열리고 다음 실행에는 토스트도 덱도 없다

#### Scenario: 다시 보기
- **WHEN** 사용자가 설정의 "튜토리얼 다시 보기"를 누른다
- **THEN** v2 전체 덱(이야기 5장 + 행동 카드)이 열리고, 닫으면 포커스가 그 버튼으로 돌아온다

### Requirement: 시작 체크리스트
투어를 본 뒤 체크리스트는 "첫 작업 맡기기"(작업 시작 성공), "다듬기 써 보기"(다듬기 결과 도착), "보고서 열어 보기"(보고서가 실제로 열림) 세 항목이어야 하며(SHALL), 모두 끝나면 사라져야 한다(SHALL).

#### Scenario: 체크리스트 완료
- **WHEN** 사용자가 세 가지를 모두 한다
- **THEN** 항목이 차례로 체크되고 체크리스트가 사라진다
