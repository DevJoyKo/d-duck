# usage-insights Specification

## Purpose
사용 통계를 바탕으로 비용을 줄이고 작업 성공률을 높일 조치를 근거와 함께 제안한다.

## Requirements

### Requirement: 앱 안 점검

"사용 개선 분석"을 누르면 선택한 기간의 집계로 점검을 즉시 실행해야 한다(SHALL). 각 결과는 제목, 근거 수치, 예상 효과, 조치(가능하면 해당 탭으로 가는 링크)를 가져야 한다(SHALL). 근거가 부족한 점검(표본 부족)은 보이지 않거나 "데이터 부족"으로 표시한다(SHALL). 네트워크·CLI 실행 없이 동작해야 한다(MUST).

#### Scenario: 캐시 비율이 낮음
- **WHEN** 최근 7일 입력 토큰 중 캐시 읽기 비율이 20% 미만이고 응답이 100개 이상이다
- **THEN** "캐시가 잘 쓰이지 않습니다" 카드가 비율과 예상 절감, 원인 후보와 함께 보인다

#### Scenario: 데이터가 적음
- **WHEN** 기간 안 응답이 20개 미만이다
- **THEN** "분석할 기록이 부족합니다"가 보이고 점검 카드는 없다

### Requirement: Claude 권고

사용자가 "Claude에게 분석 받기"를 누르면 보낼 집계 요약과 예상 비용을 확인 창에 그대로 보여 주고(SHALL), 확인한 경우에만 실행해야 한다(SHALL). 요약에는 프롬프트·응답·코드·파일 경로·프로젝트 이름·세션 제목이 들어가면 안 된다(MUST NOT). 실행은 웹 검색·문서 가져오기 외의 도구를 쓸 수 없어야 한다(MUST). 결과는 출처 링크가 있으면 함께 보이고 "참고용" 표시를 한다(SHALL).

#### Scenario: 요약 확인
- **WHEN** 사용자가 "Claude에게 분석 받기"를 누른다
- **THEN** 확인 창에 모델별 토큰·비용, 도구별 횟수·오류율 같은 숫자만 보이고 취소하면 아무것도 실행되지 않는다

#### Scenario: 실패
- **WHEN** 로그인 만료나 120초 초과로 실패한다
- **THEN** 오류가 보이고 앱 안 점검 결과는 그대로 남는다

### Requirement: 결과 보관

마지막 Claude 권고 한 개만 저장하고(SHALL) 사용자가 지울 수 있어야 한다(SHALL).

#### Scenario: 다시 열기
- **WHEN** 앱을 다시 켜고 사용 통계를 연다
- **THEN** 마지막 권고와 실행 시각·비용이 보이고 "지우기"가 있다
